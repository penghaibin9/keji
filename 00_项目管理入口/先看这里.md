## 为什么其他目录仍然保留

| 目录或文件 | 用途 | 处理原则 |
|---|---|---|
| `backend`、`frontend` | 后端和前端源码 | 保留，程序和定制源码交付需要 |
| `deploy`、`scripts` | 部署配置、运行和维护脚本 | 保留，独立部署与维护需要 |
| `tests`、`acceptance` | 自动测试与验收程序 | 保留，验证和后续修改需要 |
| `docs` | 操作、部署、接口、数据字典等文档 | 保留，采购明确要求交付；旧阶段说明只作历史参考 |
| `delivery` | 进度、交付记录，也包含执行程序和配置 | 保留，不能当成纯报告目录整体删除 |
| `evidence` | 测试与验收证据 | 保留，支持追溯；历史通过不代表当前版本全部通过 |
| `changes` | 历史代码差异 | 保留，仍被交付清单引用，不可盲删 |
| `.codex-temp` | 测试运行环境、合成数据、备份与临时脚本混合 | 暂保留；不能因名称含临时就整体删除 |
| `tmp` | 临时文档审阅资料 | 本轮未删除，后续按内容和引用逐项清理 |
| 根目录校验清单、配置和启动文件 | 历史版本核对、测试及启动入口 | 保留；历史校验清单不作为当前版本完整性的新证明 |

这些是工程材料，不要求你逐份阅读。目录多不等于采购范围多。
