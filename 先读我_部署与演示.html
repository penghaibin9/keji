按顺序演示

先讲数据和办理，再讲对接

推荐一条主线：学校总览 → 教师数据 → 资质补正 → 积分依据 → 解决异议 → 四级考核归档 → 历史证据 → Excel → 对接说明。

流程 01

学校总览与数据来路

使用账号：admin（学校管理员）

  1. 登录后停留“工作总览”，在统计周期选择“2026年度演示考核（合成）”。
  2. 查看归属培训收入、课程人次、参与教师、项目以及收入趋势；点击指标进入培训数据台账。
  3. 打开系统对接中心，说明统一认证、中台、湘培目前都未接通；展示“对接怎么开始”。
应看到：初始化后的2026年全校培训收入58,500元；全部为合成样本。正常浏览器验收会给教师二另加2条业务，届时全校金额增加1,600元。

向学校说明：这是数据汇聚与业务办理前台，不是替代学校已有系统。

流程 02

教师本人数据与独立翻页

使用账号：show_teacher（合成教师一，工号YS001）

  1. 登录，打开“培训数据台账”；先保持“全部周期”。
  2. 上方授课记录共25条，点击授课区的“下一页”；下方本人参训共23条，使用参训区自己的“下一页”。
  3. 再选择2026周期筛选：授课22条、75学时、451人次、34,100元。参训记录不增加授课收入和课程人次。
应看到：教师只能看本人；授课和参训各自翻页。首次导入现场Excel后数据会增加，不再套用初始数量。

向学校说明：看汇总能追到明细，教师参加培训与给别人授课不会混算。

流程 03

资质退回、补正与重新提交

使用账号：show_teacher → show_dept

  1. 教师进入“教师资质管理”，打开“退回待补正材料（合成）”，查看此前退回记录。
  2. 点击“编辑资料”，填写调整原因保存；可点“上传佐证”选择delivery/assets/合成佐证_不是有效证书.pdf，然后“提交审核”。
  3. 用show_dept登录，在统一待办或资质列表打开该材料，填写意见后点击“审核通过”。
应看到：材料由退回/草稿→待资质审核→审核通过，保留前后版本与审核人员。

向学校说明：演示补件有流程、有意见、有证据，而不是直接改个状态。

流程 04

资质到期提醒与受控附件

使用账号：show_teacher → show_other（对照）

  1. 主教师打开统一待办，查看“近期到期提醒材料（合成）”。
  2. 进入材料详情，查看有效期并下载原始合成PDF；说明下载必须有业务权限。
  3. 使用show_other登录，确认其列表不出现合成教师一的材料；不要对学校人员实际资料做越权试验。
应看到：到期日按部署当天加14天生成；另一学院教师看不到本人范围之外的资质。

向学校说明：到期可提醒，附件不是任何人拿到一个网址都能下载。

流程 05

积分有原始值、有公式

使用账号：show_teacher

  1. 打开“教师积分激励”，选择2026周期并筛选。
  2. 点击“计算依据”，分别查看授课学时和课程人次的原始数据、公式、批次和规则版本。
  3. 说明本套演示公式为学时×2＋人次×0.1，初始本周期合计195.10分；这是演示规则，不是学校已确认的政策。
应看到：75×2＋451×0.1＝195.10分；已归档历史不因新规则自动改写。

向学校说明：每一分能解释，后续按学校制度配置。

流程 06

先解决异议，再允许考核确认

使用账号：show_teacher → show_dept

  1. 主教师打开2026本人考核，先尝试“本人确认”：初始有未解决数据核对，系统应提示先处理。
  2. 用show_dept进入“数据核对与复核”，先将周期选为“全部周期”（此申请关联业务记录，没有独立周期），打开合成教师一的申请，填写复核结论及依据后完成复核。
  3. 确认该申请已显示完成复核，再回到主教师考核；留到下一流程点击“本人确认”，不要重复点击已提交的环节。
应看到：初始数据特意保留一个未解决核对。完成复核后才能进入下一级；第一次被拦截是应有的业务校验。

向学校说明：有争议先核对，申请人与复核人分开。

流程 07

四级考核确认与归档

使用账号：show_teacher → show_dept → show_college → admin

  1. 每个角色登录后都选择2026周期并定位“合成教师一”。主教师先“本人确认”，show_dept再“确认并提交下一级”。
  2. 用show_college确认，再用admin完成学校确认，状态变为“待归档”。
  3. admin点击“归档结果”，填写原因；下载归档证据。已归档不能再直接改分。
应看到：教师确认→教研室确认→学院确认→学校审核→待归档→已归档，初始示例考核为92.33分。

向学校说明：每一层确认有记录，最终历史结果和材料冻结。

流程 08

查看上一年度历史归档

使用账号：show_teacher 或 admin

  1. 进入三级考核管理，选择“2025年度演示考核（合成）”。
  2. 打开主教师的“已归档”结果，查看冻结规则、源数据、办理轨迹与摘要。
  3. 点击“下载归档证据”；“打印结果”需在目标浏览器实测分页后再用于现场纸质展示。
应看到：上一年度归档已通过正常四级动作生成，不是直接向数据库写入一个“已归档”标签。

向学校说明：历史可核查，不被现在的数据覆盖。

流程 09

教研室和学院各看各的

使用账号：show_dept → show_college

  1. 教研室负责人打开“教研室与二级学院管理”，查看本教研室的汇总、教师和待办。
  2. 打开“三级考核管理”的“教研室考核”标签，查看已生成、待组织复核的自身考核。
  3. 学院负责人进入对应页面和“学院考核”标签，说明范围包含本学院的两个教研室，不包含另一学院。
应看到：初始全部历史：主教研室27条授课，本学院29条。浏览器验收给同教研室的教师二追加2条后对应数量各加2。

向学校说明：管理范围跟组织关系走，不靠前端隐藏全校数据。

流程 10

Excel错误预览与明确入库

使用账号：admin

  1. 在“Excel导入中心”上传02_培训业务_错误样本.xlsx：出现1条错误，下载错误行，不能确认入库。
  2. 上传01_培训业务_正确样本.xlsx：校验通过，但还没有入库；点击“确认入库”并填写意见。
  3. 进入台账检索YS-EXCEL，确认新增2条；同一来源编号不能重复入账。演示计算最好在导入前先讲完，导入后需重算未归档结果。
应看到：预览不写业务；两行都正确才确认写入。两个样本不要混用，修错后应重新上传。

向学校说明：小白也能根据错误行反馈整理数据，不必写SQL。

流程 11

后台导出与审计追踪

使用账号：admin

  1. 在台账或考核页选择筛选条件后点“导出”，进入“导出与任务中心”。
  2. 待任务显示“已完成”后下载Excel；没有完成就刷新任务，不能把排队状态说成已生成。
  3. 进入“操作日志与安全审计”，查看刚才的审核、确认、导出及对应请求编号。
应看到：Excel是真实后台生成，操作能追到人员、业务对象和结果。任务失败先检查worker，不能跳过失败状态。

向学校说明：不是只做表格界面，实际办理和输出都有记录。

三类系统如何接入与展示边界

  1. 进入系统对接中心的统一认证、中台、湘培独立入口，展示接口准备、字段对应、任务和异常页签。
  2. 进入“对接怎么开始”，下载空白对接沟通Excel，说明先由学校/省级责任方提供协议、字段、测试条件和责任人。

向学校说明：能清楚划分你负责的产品和学校/省级系统需要配合的内容。

实施人员执行

部署分为三次明确动作

1. 先预检，等你确认

bash 开始部署.sh plan --target /opt/yueke/nondegree-r11-preview --port 18443 --out R11_只读预检_待确认.json

只生成报告，不创建目标目录。目录存在、端口占用、环境不足就停止。确认编号来自这次报告，不在包里预填。

2. 你批准后，准备独立实例

sudo python3 delivery/manage.py prepare --plan R11_只读预检_待确认.json --confirm 实际审批编号

3. 在新目录构建、安装、生成数据

cd /opt/yueke/nondegree-r11-preview
sudo bash 开始部署.sh build
sudo bash 开始部署.sh install
sudo bash 开始部署.sh seed
sudo bash 开始部署.sh status

构建要下载依赖，本包不含 Docker 镜像、已安装依赖或浏览器。真实 MySQL 8.4 安装成功后才允许填充合成数据；没有走测试模式。

完整实施细节、TLS 信任和正常浏览器检查命令见 部署操作.md。不要关闭证书校验；仅公开 CA 证书可交给你的演示电脑，私钥不能分发。
