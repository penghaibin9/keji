# R11 独立、受限访问演示资源包

## 给彭先生先看

这是一份包含R11完整工程、合成数据初始化器和演示流程的试部署资源包。不是另一份HTML原型，不是已经在你的目标服务器部署完成，也不是学校正式上线验收。

你不需要手工建业务表或写SQL。把完整包交给Codex，先运行只读预检，给你看目录、端口和资源占用建议；你确认后再执行新环境安装。服务器操作需要在你的实际机器上完成，本资源包没有远程连接你的服务器。

默认方案：独立目录 `/opt/yueke/nondegree-r11-preview`，独立MySQL 8.4容器、文件目录与随机Compose项目名；网页仅监听服务器 `127.0.0.1:18443`。不占用已有80/443/3306，不改现有网站Nginx，不主动修改主机防火墙策略，不直接开放公网。Docker创建本项目网络时会自行管理其网络规则。新服务仍会使用服务器资源，不能承诺零资源影响。

## 执行环境

目标为Linux服务器，已有本地Docker Engine 28及以上、Docker Compose v2、Python3.10及以上、OpenSSL。只读预检会检查实际情况，不自动安装或升级系统工具。建议至少8GB可用磁盘、5GB可用内存；镜像构建与试运行仍需观察实际负载。仅对新项目叠加delivery/compose.restricted.yml：数据库1.5GiB、API1.5GiB、worker1GiB、前端256MiB，上限合计4.25GiB，另需Docker及操作系统余量；CPU分别限1、2、1、0.5核。限额不是性能达标证明，构建阶段仍需安排空闲时段。缺条件先报告并请你确认方案，不绕过检查。

源码包不含Docker镜像、已安装Python依赖或浏览器。构建依赖网络下载；也可由实施人员在有网络的环境按同版Dockerfile构建后受控导入，但需保留版本/摘要证据。不能把源码ZIP称为“完全离线一键安装包”。

## 1. 只读预检：只生成报告，不创建目标目录

在解压的原包目录执行：

```bash
bash 开始部署.sh plan --target /opt/yueke/nondegree-r11-preview --port 18443 --out R11_只读预检_待确认.json
```

该报告列出系统、现有容器/监听端口、空闲内存/磁盘、拟用目录及端口。`BLOCKED`时禁止继续；没有Docker、旧版本Docker、非本地Docker上下文、目录已存在或端口冲突都要先处理。端口18443只是建议，不是已经分配。

Codex须把报告解释给你。先确认本次只建立独立环境，不改现有服务。`approval_id`绑定报告内容和目标机器，有效期12小时。不要自动替你确认，不要篡改报告去掉阻断。

## 2. 你确认后才准备文件

以下`审批编号`由实际预检报告产生，不在包里预设：

```bash
sudo python3 delivery/manage.py prepare --plan R11_只读预检_待确认.json --confirm 审批编号
```

这一步新建独立目录，复制完整R11，生成该实例自己的TLS证书、数据库分权密码与管理员临时密码。已有目录无论是否为空都拒绝覆盖。准备中断时保留现场，不能删标记继续装。

## 3. 构建、安装、填充合成数据

转到刚创建的独立目录：

```bash
cd /opt/yueke/nondegree-r11-preview
sudo bash 开始部署.sh build
sudo bash 开始部署.sh install
sudo bash 开始部署.sh seed
sudo bash 开始部署.sh status
```

`build`使用原R11的Dockerfile，且构建上下文白名单不包含任何新密码、证书私钥或运行数据库。部署后不要在含有delivery-state的目录手工运行docker build或docker compose build，应继续使用这个白名单构建入口。

`install`沿用R11原始空校安装、正式迁移、来源核验、分权授权与HTTPS健康检查；要求实际数据库版本是8.4。数据库只在新容器内，内部库名nondegree不会指向服务器现有MySQL。只有真实安装成功才生成`delivery-state/mysql-installation.json`。

`seed`通过正常本地账号登录、正常首次改密和真实业务接口写合成数据，不开启ND_SEED_ENABLED，不执行直接写业务表的SQL。9个账号密码分别随机生成。写入逐步有私密日志和幂等键；已完成后重复调用只读返回，不重复灌数据。中途失败不要删日志，不要人工把状态改成COMPLETE；超过12小时的未完成任务停止自动续跑，交给实施人员对账。

## 4. 安全拿到账号和访问入口

服务器独立目录中：

- `delivery-state/账号密码_仅管理员保管.txt`：人可读凭据，权限0600。
- `delivery-state/accounts.private.json`：浏览器验收工具读取的凭据，不得公开。
- `client-access/R11_Local_CA.cer`：此实例的公开CA证书，不是私钥。
- `client-access/Windows_受限访问.ps1`：SSH隧道辅助脚本，不修改浏览器信任、不安装程序。

通过已有可信SSH/SFTP安全传给你本人。不要把账号文件上传官网、贴到群里、放GitHub或打进公开资源包。切勿发送`ca.key`、`server.key`、数据库密码文件。

在Windows用现有SSH连接建立隧道：

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:18443:127.0.0.1:18443 SSH用户名@服务器地址
```

非默认SSH端口加`-p`参数；保持窗口打开。随后浏览器访问 `https://127.0.0.1:18443`。这是隧道入口，不是互联网公共网址。远程/本地端口必须与实际计划一致，不可随意换成本机不同端口，因为系统核验来源。

首次使用前，实施人员先从可信SSH核对CA证书指纹，再经你确认，将这个实例的公开CA证书导入你本人的“受信任的根证书颁发机构”。仅用于你的演示电脑，不向学校大量分发。不要关闭TLS校验，不要忽略红色证书警告。演示结束后可删除此根证书；证书过期需受控更换而非改浏览器时间。

用户能打开页面不表示学校用户都能访问。给学校远程展示优先屏幕共享；需要公共子域名、VPN或IP白名单时另做方案，先确认再配置，本包不会自动开放公网。

## 5. 真浏览器验收（可以由你电脑上的Codex执行）

正常浏览器先能打开上述受信任HTTPS入口。实施电脑安装独立的Playwright工具环境，可用已安装的Microsoft Edge，避免覆盖你现有浏览器。不要在服务器未经确认运行自动系统依赖安装脚本。

把该实例的`accounts.private.json`、`data-summary.json`和`mysql-installation.json`安全复制到实施电脑私密目录；不是从本公开包中找密码。Windows私密目录应仅允许本人账户及必要的管理员访问，不能放在共享文件夹或共享同步盘；脚本不会自动修改Windows ACL。数据和MySQL来源编号必须一致。

```bash
python delivery/browser_acceptance.py --origin https://127.0.0.1:18443 --credentials 私密目录/accounts.private.json --data-summary 私密目录/data-summary.json --mysql-proof 私密目录/mysql-installation.json --output 私密目录/浏览器验收结果 --channel msedge --headed --confirm-synthetic-writes
```

工具走真实网页登录、保存、刷新回读、分页、附件上传下载、资质提交和审批、四级考核、Excel预览确认及后台导出，不伪造接口返回。它使用合成教师二处理验证，主教师仍保留给现场演示。不要拿SQLite控制回执伪造MySQL凭据。测试报错时保留记录，修复后复测；没有PASS就不称“稳定可演示”。浏览器报告默认保存在实施电脑指定的输出目录，需要与服务器mysql-installation.json中的实例编号对照；status命令不会自动读取你电脑的报告。

浏览器检查会真实改变教师二的数据：新增1份资质、2条培训记录，将教师二当期考核归档；主教师的当前考核仍待本人确认。重复执行会遇到已归档/重复来源等保护，需要核对现状；不可直接删除保护或改状态来重复演示。

打印结果的真实分页与纸质打印需人工补验；本轮没有完成打印机验证。学校接口、并发性能、真实双轨样本和正式验收仍属于另一个阶段。

## 6. 开始演示

阅读同目录`核心演示流程.json`或根目录的HTML/PDF操作手册，按12个流程顺序展示。关键依赖：主教师初始有一条未解决的数据核对，要先由负责人完成复核，才能继续主教师考核确认。负责人查看“数据核对与复核”时请先选“全部周期”，因为该核对关联培训业务而没有单独周期。这是准备好的业务场景，不是异常。

业务金额与公式只用于展示。主教师2026年初始22条授课、75学时、451人次、34,100元，积分195.10分、考核92.33分；打开“全部周期”会额外看到2025年3条历史授课。

## 7. 停止、继续、备份与回退

只停止新项目，不删除数据，也不停止你的学生SaaS或其他网站：

```bash
cd /opt/yueke/nondegree-r11-preview
sudo bash 开始部署.sh stop
```

维护状态无异常且此前安装成功时，继续开启：

```bash
sudo bash 开始部署.sh resume
```

给自己保留展示前备份（会短暂停止本演示环境，不影响其他项目）：

```bash
sudo bash 开始部署.sh backup
```

备份使用原R11脚本生成数据库与附件、来源证明、47表内容对账回执和摘要。生成备份不等于已经验证恢复。建议由实施人员在另一套全新独立实例中按原包`scripts/restore.sh`验证恢复；原环境不可直接覆盖。

第一次部署的回退方式是停止这个独立项目，因为原系统和主机Nginx没有被改。脚本不提供自动删库、清空目录、Docker全局清理或删除维护标记。多次现场展示可建立新的考核周期/资质，或受控创建新的独立演示实例；不能重置已归档历史。

## 8. 禁止的操作

不得手工stamp、修改installation_provenance、关闭release_guard、把ND_ENV改为test部署、设置ND_SEED_ENABLED=true、导入学校真实人员数据、开公网数据库端口、启用真实外发、把本包全部条款标成采购验收通过。
