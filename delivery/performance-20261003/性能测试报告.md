# 本机性能测试报告（2026-10-03）

测试时间：2026-10-03 晚上，在你的笔记本上跑的（i5-12500H，16GB 内存）。用的是 SQLite 数据库，压测程序和系统装在同一台电脑上，所以结果只能作参考，不能代替学校服务器 + MySQL 上的正式测试。

测试数据：121 个组织、3331 个账号、63,868 条培训记录、6400 条资质、6400 条考核，按一所中等规模学校全年的数据量造的。

| 测什么 | 结果 | 结论 |
|---|---|---|
| 3000 人同时在线 | 3000 个账号全部登录成功，0 个错误；逐个检查时 2983 个会话正常，17 个是检查请求本身排队超时 | 达到 |
| 100 人同时操作，普通页面（待办、台账、资质列表、首页） | 95% 的请求在 2.5 秒内返回，测试设定的标准是 3 秒 | 达到 |
| 100 人同时操作，复杂查询（驾驶舱、考核列表、组织工作台） | 95% 的请求在 3.2 秒内返回，测试设定的标准是 5 秒 | 基本达到 |
| 最慢的一项：全校跨年对比统计 | 95% 的请求在 10.8 秒内返回，超过 5 秒标准 | 未达到 |
| 出错率 | 约 0.16%，是 SQLite 同一时间只允许一个人写数据造成的，换成 MySQL 后应能消除 | 待 MySQL 复测 |

说明：这次压测里，每个模拟用户收到结果后马上发下一个请求，中间不停顿。真实用户每次操作之间会看几秒页面，所以真实的 100 人在线压力比这次小得多。

结论：13.7、13.8 两条在本机上**基本达标，但还不能算正式达到**。要正式达到，需要到学校服务器上用 MySQL 再测一次，并顺手优化全校跨年对比统计这一项。完整数据在 `delivery\performance-20261003\`。
