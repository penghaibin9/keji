## 一、填写规则

| 字段 | 填写要求 |
|---|---|
| 编号 | `RECT-三位序号`，一经分配不再复用；问题合并时在“整改措施”注明并入编号，不删除原行 |
| 发现日期 | YYYY-MM-DD |
| 来源 | 采购逐条核验 / 自动测试 / 试运行 / 用户反馈 / 联调 / 学校检查 / 验收评审，并注明文档或记录编号 |
| 对应采购条款 | 采购清单“项.条”编号，如 12.6；无对应条款填“—” |
| 严重程度 | **高**＝采购明确要求、验收必查或影响数据安全/正确性；**中**＝功能已有但不完整；**低**＝体验或非强制改进 |
| 责任人 | 供应商责任人姓名；依赖学校的同时填写学校对接人 |
| 整改措施 | 具体做法；完成后补充修改文件/配置与回归证据（测试名称、截图、记录编号） |
| 计划完成 / 实际完成 | YYYY-MM-DD |
| 验证人 | 完成后由非整改人复核；学校确认的问题由学校人员签认 |
| 状态 | **整改中**＝已确认、正在处理；**待学校提供**＝需学校资料/环境/签字才能继续；**已整改待验证**＝供应商已修复并在相同环境回归；**已关闭**＝学校或验收责任方确认关闭；**不予整改**＝双方书面确认，须注明依据 |

不得因“无法复现”直接删除历史问题；改为“已关闭”时须在“整改措施”写明复核过程。标注【依赖学校】的问题，我方先完成通用能力，学校资料到位后再完成最终验证。
