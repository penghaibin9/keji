## 二、四项核心整改

| 问题 | 本轮代码处理 | 安全边界 |
|---|---|---|
| 已发布连接在 24 小时后失效 | 24 小时只限制新发布的证明使用期限；已经发布的授权不因时钟经过而中断 | 地址、配置、映射、适配器或凭据变化，原发布授权仍失效 |
| 超过 1,000 条不能续拉 | 工作进程每次处理一页，事务提交批次与恢复点；后续页继续处理 | 不猜测分页终点，拒绝游标循环、跨页重复和总量不符 |
| SSO 预览与实际登录不同 | 预览调用实际登录身份解析器，统一根路径、启停、角色列表和组织对应 | 不创建会话，不写身份绑定，不把学校外部管理员角色自动变成本地管理员 |
| 回调和测试不成流程 | 正式与试登录回调由服务端只读生成，增加独立浏览器试登录和分层证据 | 试登录不切换实施人员账号；TEST_ONLY 证明不能发布正式连接 |

分页任务在中断后保留已经确认的前页，从未完成页继续；这不是“整次同步可以无条件回滚”。
人工采集每页先预览、确认后再继续；自动采集必须有原有学校管理员批准，整个运行结束后才推进计划的增量检查点。
每个批次保留摘要和回执；数据质量错误与失败重试保留，不靠提高一次性内存上限掩盖问题。

## 三、学校信息处可见流程

接入资料 → 协议与环境 → 回调及凭据 → 字段与身份范围 → 测试与样本预览 → 发布与同步计划 → 日志诊断及交付。

资料、配置、测试、发布、健康、学校验收分别显示，不再用一个 CONNECTED 或完成百分比代替全部状态。
资料登记有责任人、文档/证据编号和确认日期，不再因连接成功自动显示资料齐全。
配置编辑写入独立草稿，保存和试验不会改变生效连接；发布前再次核对权限、版本、配置摘要、适配器和凭据。
发布会暂停原同步计划，需要明确重新批准；健康检查仅记录最近检查，不撤销发布授权。
诊断保留受控阶段、中文建议、追踪号及允许的状态信息，不暴露密码、私钥、令牌或原始异常正文。
交接包下载受管理员、同步权限和导出权限共同保护；学校验收始终待学校另行签认。
原有运行日志、任务、入站批次和定时计划保留；旧配置页深链接兼容，但管理员默认入口集中为七步流程。

## 七、使用这份成果

优先让本地 Codex 在独立副本中复核源码，确认没有与其他窗口的新改动冲突后再融合。不要直接解压覆盖学校正式服务器。
修改包中的 APPLY_PATCH.py 默认只核查，不改文件。它按每个文件的原始基线校验；遇到本地已改动会明确拒绝，而不是猜测合并。

```powershell
python APPLY_PATCH.py --root "你的keji仓库副本目录"
python APPLY_PATCH.py --root "你的keji仓库副本目录" --apply
```

第二条命令才实际应用，事先备份要修改的原文件；工具不操作数据库、不安装依赖、不提交或推送 Git。
使用完整源码包时应解压到新的独立目录，按既有部署文档完成独立 MySQL 8.4 验证；安装依赖和学校部署环境不包含在源码 ZIP 中。
