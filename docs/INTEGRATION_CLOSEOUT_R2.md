# 统一认证与接口适配中心 R2 收口说明

日期：2026-09-23
连续基线：R1 b0f9ca34251c8fec688393ac588e445377250450，Windows CRLF 测试兼容提交 e63eaa39701ebdd32c7e3fd682ec07c65dc627c4。

本轮继续在原项目目录施工，没有新建第二套业务系统，没有增加菜单，也没有修改学校业务数据库或部署服务器。

## 1. 本轮新增能力

R2 在 R1 七步实施流程内补齐两类交付能力。

### 凭据 / 证书安全资产登记

只登记凭据类型、安全保管方式、轮换责任人、证书 SHA-256 指纹、证书主题/签发方、有效期和轮换日期。页面不接收或回显真实密码、令牌、密钥、私钥或证书正文。证书过期、30 天内到期、轮换到期和 30 天内需轮换可以明确显示。登记记录绑定当时的生效连接版本和草稿版本，避免并发误写。

### 学校接口验收台账

SSO、学校数据中台、湘培直通车分别使用固定验收项，不允许任意删减。“通过/未通过”必须登记学校联系人、核对日期和证据编号；“待确认”可以先保存。

最终签认必须同时满足：当前版本未变化、全部验收项通过、真实发布仍有效、实施资料齐全、凭据/证书安全资产有效、当前版本真实健康检查通过。湘培仍有权威来源缺口时禁止最终签认。

验收后如果配置变化、凭据轮换或当前健康状态失效，历史签认保留，但当前状态自动变为“需重新确认/需复核”，不会继续显示已验收。

## 2. 交接包增强

/api/connections/{id}/handover.zip 现在为 R2 交接格式，包含：

- implementation.json：机器可读配置、状态、草稿、资料、安全资产元数据和验收台账；
- 接口实施交接工作簿.xlsx：学校信息处/实施人员可直接打开，包含“状态总览、资料清单、字段映射、凭据证书元数据、学校验收台账”5 个工作表；
- README.md：交接边界说明。

工作簿和 JSON 都不读取服务器真实凭据，不包含密码、令牌、私钥或证书正文。

## 3. 当前七步流程

接入资料 → 协议与环境 → 回调及凭据 → 字段与身份范围 → 测试与样本预览 → 发布与同步计划 → 日志诊断及交付。

没有为 R2 增加新的左侧菜单。安全资产放在“回调及凭据”，验收台账放在“日志诊断及交付”。

## 5. 仍然不能对学校宣称完成

以下内容仍必须等学校/省平台真实资料和环境：

- 学校统一认证、数据中台、湘培直通车真实协议、地址、凭据和网络路径；
- 学校脱敏真实样本、异常样本和联调窗口；
- 湘培的培训计划、学习过程、结业结果、证书信息四类数据权威来源；
- 学校真实四级权限越权矩阵、真实账号登录/停用/调岗/兼岗验证；
- 积分和考核真实案例双轨 100% 一致；
- 学校服务器 100 并发/3000 在线相关性能验证；
- 正式试运行、问题整改、培训和最终签认。

因此 R2 的“学校已签认”只能由服务端在当前版本满足前置条件、且学校签认信息被明确登记后显示，不能由本地测试自动生成。
