# R5 新空校与旧库边界

## 一、允许与拒绝

| 目标或来源 | 处理 |
|---|---|
| 全新无业务表、无视图的独立空库 | 允许进入 canonical 安装检查；真实 MySQL 8.4 验收仍待执行 |
| 已完整安装同一 canonical 基线、来源/结构均匹配 | 允许核验及同基线重复迁移 no-op；不是跨版本升级证明 |
| 仅有 Alembic 版本号、缺来源记录 | 拒绝；不能通过 stamp 补救 |
| 旧 20260917_0001/0002、未知版本、有业务表无来源 | 拒绝升级，不删表、不改数据、不补造标记 |
| 带完整 manifest 和 canonical 来源回执的同基线备份 | 仅可在独立空目标核验恢复；源/回执/恢复库安装身份须一致 |
| R4 或缺 provenance 的旧备份 | 在调用 Docker 和修改目标前拒绝 |
| 已有业务库或非空附件目标 | 拒绝覆盖恢复 |

## 二、固定文件

正式迁移仅 `backend/alembic/versions/20260918_0001_canonical_fresh_school.py`，`down_revision=None`。冻结 DDL 包含 46 张应用表（44 张 R4 表 + installation_provenance + connection_checks）；Alembic 版本表另计，共 47 张。旧 0002 原文移入 `alembic_legacy_unverified`，不参与正式迁移发现；缺失父迁移仍未找回。

`backend/canonical_release.json` 锁定新迁移、旧迁移证据及结构契约的 SHA256。后续正式发布不能编辑这些冻结文件冒充原安装；真正新的版本必须另行设计、审查和验收迁移，不复用此基线覆盖现有库。

## 三、安装来源不是一个随便填写的布尔值

来源行只由新空库基线的最后一步写入，包含唯一安装 UUID、基线号、来源类型、结构契约摘要及安装时间。运行账号对来源表及 Alembic 版本表只有 SELECT 权限。迁移、生产应用启动、worker、就绪检查、CLI 和备份/恢复均核验来源及结构。

结构核验覆盖表集/视图、字段类型族、字符串长度、数值精度、可空性、主键、外键对应列、唯一约束、所需索引、CHECK 表达式及 MySQL InnoDB。它不是全物理结构比较，不涵盖所有数据库实现细节；还必须做真实 MySQL schema 验收。

这套机制能拒绝单独改版本号、缺失来源、部分建表及常见结构漂移，**不是对恶意高权限 DBA 的密码学防伪证明**。能同时改库、程序和校验清单的管理员仍属于可信部署边界；迁移凭据必须独立保管，不能交给应用账号。

## 四、失败安装不得擅自清库

MySQL 多条 DDL 不能当成一笔可以整体回滚的事务。若中途失败，保留错误日志和部分库现场；不得写来源行、手工 stamp、自动删库或继续服务。排查修复后，在审批后的另一独立空库重试。已生成来源但版本号未正常完成的异常现场同样拒绝。官方参考：Alembic Commands 的 stamp 说明；MySQL 8.4 Atomic DDL Support。

## 五、备份恢复

备份在维护停写期间验证安装身份，写出 `installation-provenance.json`，与数据库 dump、附件和 manifest 一并哈希。恢复前校验文件、来源类型和结构契约；恢复后先核验数据库身份与备份回执完全一致，再执行清理。

恢复清理会撤销全部旧会话、提升账户会话版本、重置管理员临时密码并强制首次改密；同时断开全部外部接口、使旧连接验证过期、取消定时自动入库批准、阻断待执行/重试/运行中的外部任务并清除任务租约。已完成同步证据保留，不伪造远端回滚。重新联调前不得重放旧任务。

## 六、当前验收

SQLite 专项仅证明控制流和拒绝路径；MySQL 方言编译仅证明冻结建表/索引语句可编译。本轮没有真实 MySQL 8.4 迁移、升级或恢复演练，不得将这两类输出填成现场 PASS。
