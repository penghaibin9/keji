# 培训方案与课件（2026年10月12日）

本课件配套《用户操作手册》《管理员操作手册》《权限配置说明》，按当前菜单和业务流程编写。培训演练使用隔离合成数据，不录入学校真实个人信息；没有新增或冒用真实业务截图。正式认证、数据中台及现场验收状态由学校联调记录说明。

## 一、培训安排

| 场次 | 对象 | 建议时长 | 核心目标 |
|---|---|---|---|
| 教师 | 普通教师 | 1.5小时 | 登录、本人培训与学分、积分申报、多份材料、一次补正、资质及考核核对。 |
| 教研室 | 负责人及经办 | 3小时 | 本组织范围、资质与考核办理、导入错误处理、连续办理及回避。 |
| 二级学院 | 学院负责人及经办 | 3小时 | 项目备案与结项、学院台账、积分初审、年度自评与学院考核环节。 |
| 学校管理员与归口 | 业务管理员、信息中心、职责人员 | 1天 | 授权及调岗、制度口径、职责、归档与批量、代码对照、正式安装及备份恢复。 |

学校与供应商另行确定时间、地点、人数、讲师与签到负责人。教室准备可访问隔离培训实例的浏览器、投影和四类培训账号；临时口令通过受控方式交本人，不印在课件中。首次本地登录练习改密，认证演示须明确是否实际接通。

## 二、教师课件

1. **入口与身份**：打开学校地址，点击“登录工作台”；首次本地登录完成“修改并重新登录”。“学校统一认证登录”仅在入口具备条件时显示；认证成功仍使用本地角色和组织授权。出现“人事调岗 · 授权待确认”联系管理员核实。
2. **工作总览与数据**：核对本人身份、待办与统计周期；“个人数据看板”“培训数据”“授课与学分”分别查看业务、授课与两学期学分。课程缺学分要联系源系统更正，不能当作零分。
3. **社会培训积分申报**：“教师积分激励”→“社会培训积分申报与认定”→“本人积分申报”，选择项目，填写依据并一次选多份材料，核对每份上传结果，确认提交还是草稿。
4. **补正一次办完**：打开“补正及辅助积分”，查看“退回意见与已有材料”，补齐错误内容和失败材料，使用“保存补正并重新提交”。提示尚未提交时处理阻断原因，保留同一申报，不重复建件。
5. **确认与历史**：查看积分、资质和教师考核依据，有误在“数据核对与复核”提出核对；已归档记录只能按“申请追加更正”追溯处理。
6. **个人导出**：进入“导出下载”，核对生成状态与本人范围，权限变化后旧文件不能继续下载。

教师练习：完成一份多材料积分草稿，读取退回意见后补正，核对一条授课学分异常和一条本人考核；培训人员核验对应状态及审计，不能只看提示框。

## 三、教研室课件

1. 本组织数据范围与本人回避；“学院与教研室”“统一待办”按实际授权查询。
2. 资质审核核对材料，教师考核教研室环节使用“确认并提交学院”，有问题写明意见后“退回教师核对”。
3. 连续办理先看当前材料与依据，再执行并查看下一条；“查看下一条”本身不会办理。
4. “表格导入”模板、上传、预览和确认分别核验；有错误时“下载错误明细”或“放弃本批”，理解整批未入库与审计保留。
5. 社会培训职责与角色不同，没有职责或有利益冲突时交由合格替代人员办理。

教研室练习：一条有错表格放弃、一条无错表格确认、一条非本人考核核对后确认；核验别的教研室记录不能访问。

## 四、二级学院课件

1. “培训项目管理”“培训课程管理”“培训基地管理”“培训成果”的登记、备案、结项和认定阶段；保存不等于审批完成。
2. “学院台账与口径检查”核对学院来源、归属人次与个人分配；本页数和全部历史数区别。
3. 院长初审须学校配置对应职责，后续归口、分管副校长、教学秘书按环节流转，本人事项由其他人员办理。
4. 教师考核学院环节使用“确认并提交学校审核”；“学院社会培训年度考核”完成自评，理解财务、成果、纪检核验与委员会评审。
5. 退回补正和核对必须办结再向下流转，已归档内容保留历史证据。

学院练习：核对一个项目结项材料、一次非本人积分初审、一条教师考核学院确认及一份年度自评；缺口径或职责时如实记录阻断。

## 五、学校管理员与归口课件

1. **账号与权限**：组织、角色、管理员身份分别核验；人事调岗后重新确认授权，检查旧会话和旧导出失效。
2. **规则与配置**：制度口径和校历由学校书面确认；“归属培训收入”达标值按学校考核细则填写，试算后启用新版本，不改归档历史。
3. **审批职责**：“社会培训制度口径”→“配置审批职责”，落实院长、归口、分管副校长、教学秘书、财务、成果、纪检、委员会名单及替代人员。
4. **集中办理**：“待归档清单”核对待归档积分、更正和教师考核。批量仅积分认定与教师考核同类同环节、当前页默认20条以内；“逐条核对确认”后逐条执行，成功与未办理分别记录。
5. **导入与代码对照**：错误终态、放弃留痕、确认入库；“代码对照（学校码表）”登记在职、类别、单位、学历、学位、课程性质，原码“待码表”不代替学校解释。
6. **对接与同步**：四张中台表与业务手工录入范围区别；字段对应、本地校验、真实连接、采集完成和确认入库分别展示，私有凭据在学校服务器受控配置。
7. **运行与备份**：正式配置和新学校安装入口、每日备份维护窗口、默认保留7份、服务器外副本、隔离空目标恢复、维护标记、诊断编号、证书更换及升级前保存旧镜像。
8. **签认**：学校真实登录、四角色、备份恢复、双轨结果、性能和最终验收分别记录；训练数据不能进入正式验收库。

管理员练习：重新确认一个调岗培训账号，配置合成职责并核验本人回避，填写学校样例考核达标值后试算，演示一页同环节批量办理和失败原因，导入完整样例码表，在独立空目标完成获授权的备份恢复演练。没有真实运维环境时该部分记未实施，不能替签。

## 六、培训记录与反馈

培训签到记录包含日期、场次、角色、参与人及签名，由学校受控保存；不要将实名签到表、照片或录屏装入公开源码包。实操记录逐项注明成功、被正确拦截或未完成，附业务编号及待改事项。

反馈内容：能否独立登录与改密、是否理解本人范围、是否会处理退回和失败材料、是否会区分草稿与提交、是否理解批量限制、是否知道找谁处理口径/码表/授权问题。未掌握项安排补训，产品缺陷记入试运行问题清单，不靠口头绕开。

真实学校认证、数据中台、异机恢复与验收未完成时仍按相应清单保留待现场验证。
