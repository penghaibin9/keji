# 管理员操作与运维手册（2026年10月12日）

适用于学校本地正式安装与后续运维，迁移头为 `20261012_0004`。本文为实施步骤说明；本轮没有在学校主机安装、改配置或恢复真实数据库。日常业务和角色操作见《用户操作手册》《权限配置说明》。技术步骤由获授权的部署管理员执行。

## 一、正式接收与新学校安装

校验同版 `SHA256SUMS`、`release-metadata.json`、三个镜像内容标识及全部离线分卷。解压后运行 `python3 scripts/check_assembly.py --strict`，检查完整源码和迁移链。不能混用旧源码、新网页或不同基线镜像。

学校确认主机、目标目录、端口、域名、证书、部署管理员、恢复管理员及服务器外备份位置。新装只允许新学校空目标，不能把新装命令用于旧库。先加载校验后的离线镜像，配置工具使用明确版本标签，正式安装不重新猜镜像版本。

```bash
python3 scripts/deployment_config.py prepare --help
```

按该帮助填写学校名称、正式访问地址、后端与网页及数据库镜像标签、证书和私钥，使用 `--new-school-only`。配置工具不会覆盖既有私有配置，并核验域名与证书匹配、数据库账号分工等条件。配置完成后：

```bash
python3 scripts/deployment_config.py verify
sudo bash scripts/install.sh --initialize-new-school
```

安装迁移与初始化成功后，由指定管理员本人领取临时口令，首次本地登录改密。初始账号不承诺外部系统已接通；业务初始化与合成训练数据是两回事。没有部署授权、空目标确认及恢复保护时不得开始。

## 二、账号与制度日常管理

核验学校根、学院、教研室组织关系与四类角色。学校层级账号与学校系统管理员身份分别配置；拥有学校角色不自动获系统管理权。人员离职、调岗或职责调整后核对旧会话、导出和附件权限失效情况。

“规则与配置”维护周期、计分规则、制度口径和校历。规则先试算后启用，达标值按学校细则填写。社会培训审批职责须落实到有效账号；院长、归口、分管副校长、教学秘书及年度考核核验人员的权限和回避分别检查，教学秘书等环节安排替代人员。

“对接与同步”按学校资料核对身份对应、四张表字段与代码对照。真实密钥、私钥和连接串只放在学校受控配置目录，通过安全渠道交接，不进入源码、交付包、截图或操作日志。

## 三、每日检查与诊断记录

“日志与运行”中的“运行与备份”显示数据库、后台任务、存储及最近备份。健康接口成功只是基础检查，还须正常账号登录、关键业务、附件下载和相应权限拒绝。关注磁盘空间、异常任务、备份时间和证书有效期。

| 记录 | 位置或入口 | 说明 |
|---|---|---|
| 部署错误诊断 | `runtime/logs/deploy-diagnostics.log` | 按阶段、诊断编号查看；程序遮蔽连接串、口令等敏感内容。 |
| 成功维护记录 | `runtime/logs/maintenance-*.json` | 记录本次维护结果和持续时间。 |
| 未完成维护标记 | `runtime/maintenance/active` | 失败后维持业务关闭；没有核验恢复条件不得直接删掉。 |
| 容器服务记录 | 部署组合工具的日志命令 | 后端、任务、网页及数据库分别查看，避免整机或无关系统重启。 |
| 业务安全审计 | “安全提示与操作日志” | 查看登录、配置、授权、导入导出、核对、审批和归档留痕。 |
| 备份回执 | `runtime/backups/*.receipt.json` | 摘要已核验不等于恢复演练已通过。 |

诊断日志只交有权运维人员，不整份公开。业务审计长期随库保存，但容器日志按大小轮转不保证保存六个月；学校日志留存要求应由信息中心确认并配置集中留存方案，见安全自查表。

## 四、每日备份与保留份数

当前备份入口会进入维护窗口、停止业务写入服务，备份数据库与附件，校验安装身份及数据库对账记录，成功后恢复原先运行的服务。因此每日定时执行要安排学校批准的低峰维护时段，不是无感在线备份。

```bash
sudo bash scripts/backup.sh --allow-maintenance-window
```

备份内容在 `runtime/backups/` 时间目录内，含压缩数据库、附件、安装来源、数据库对账、摘要清单和学校配置副本。配置副本含私有内容，备份目录应仅部署管理员可读；加密转存并控制密钥交接。成功回执仅表示摘要校验通过。

经学校确定维护时段后，可由部署管理员配置每日凌晨2时的定时任务。下面路径仅为独立正式工程示例，须改成学校确认目录；此文不自动安装定时任务：

```cron
0 2 * * * cd /opt/nondegree && bash scripts/backup.sh --allow-maintenance-window >> /var/log/nondegree-backup.log 2>&1
```

任务以已授权的部署管理员身份运行，日志设置为仅管理员可读。每天核对任务退出结果、备份回执、摘要和恢复业务后的登录；任务失败须告警，不只检查有没有文件夹。

保留工具默认保留最近7份完整备份；学校可决定更长周期。清理和备份是两个独立动作：先把备份完整复制到学校指定的服务器外位置并核对摘要，再预览清理候选：

```bash
sudo python3 scripts/prune_backups.py --keep 7 --dry-run
```

核对候选与至少一份已成功隔离恢复的保护点后，再在已批准保留策略内执行：

```bash
sudo python3 scripts/prune_backups.py --keep 7
```

只处理规定时间目录和安全文件；异常目录、链接或未完成目录须单独检查。服务器本盘备份、服务器外副本和已验证恢复分别记录，不混写为备份闭环已完成。

## 五、隔离空目标恢复演练

准备另一台测试主机或完全独立的新空目录、空数据库和独立端口，确认不会覆盖学校现库或现附件。使用匹配版本的完整源码、镜像、备份和受控配置；目标管理员临时口令由恢复目标的私有配置提供，不能写在命令中。

先校验备份摘要、安装来源与数据库对账文件，再在恢复目标工程目录执行：

```bash
sudo bash scripts/restore.sh --into-empty-school /srv/nondegree-backups/20261012T000000Z-00000000 admin
```

上述备份目录为格式示例，必须换成实际已核验备份；不会创建示例备份。恢复入口拒绝已有业务数据目标，校验数据库行摘要与附件摘要后进行迁移和恢复清理：旧会话失效、接口变为待对接、旧连接证明过期、自动采集及写入任务暂停，避免重放外部写入。

指定管理员重新登录并首次改密，核对代表业务、权限、附件、积分与考核归档证据；与备份源逐项对账并记录结果。隔离演练不能调用学校真实外部接口或发送真实消息。恢复后的重新连接、定时计划与正式开放需单独核验和授权。

## 六、维护标记与故障处理

操作失败时立即停止后续升级或发布，记录诊断编号和阶段。检查 `runtime/maintenance/active`、正在运行的维护进程、当前代码镜像、数据库迁移状态、备份与附件；系统不会自动重新开放业务写入。

未完成维护标记不能当成“缓存”随意删除，也不能靠重启整机或清空数据解除。由部署及恢复管理员制定与当前数据结构兼容的恢复方案，在隔离目标验证后执行；只有核对数据、附件、服务、角色及登录均通过并确认没有其他维护持有者，才按批准方案解除标记和开放业务。维护标记跨异常重启的行为仍需学校演练，不在本手册中宣称已经补齐。

## 七、证书更换与版本升级

证书到期前30天安排更换，取得学校正式新证书与匹配私钥。先保留旧受控文件及属主、权限，临时核对域名、有效期和配对；收到更换授权后替换学校受控证书，运行配置核验，只重建目标网页服务，再真实浏览器检查证书、登录、样式图片与刷新。失败恢复匹配的旧文件；不得关闭证书校验或改为不安全地址解决问题。

升级前记录当前镜像标签与内容标识，保存旧镜像和摘要，保留旧程序版本目录，并验证数据库与附件备份及恢复方案。旧镜像示例命令如下，标签必须替换为当前实际版本：

```bash
docker image save -o /srv/nondegree-backups/previous-images.tar yueke/nondegree-api:previous yueke/nondegree-frontend:previous yueke/nondegree-mysql:previous
sha256sum /srv/nondegree-backups/previous-images.tar
```

校验候选源码、同版镜像、迁移头及所有回归后，在批准维护窗口用现有升级入口：

```bash
sudo bash scripts/upgrade.sh --allow-maintenance-window yueke/nondegree-api:new yueke/nondegree-frontend:new
```

示例标签不能原样用于正式升级。程序入口执行维护、备份、迁移、权限及健康校验；失败保持写入关闭。代码回退先确认与当前数据库兼容，不能自动数据库降级或用旧备份覆盖新业务。

## 八、现场签认与责任

学校填写真实目录、域名、备份位置、保留期限、维护时段、联系人及响应安排。完成正常账号登录、四角色业务、真实统一认证、数据中台、双轨比对、性能及异机恢复后分别签认。本文中的命令和方案没有替学校完成这些验证，也不承诺未签订的售后时限。
