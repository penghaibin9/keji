# 管理员操作手册

## 1. 首次初始化原则

生产首次安装必须先完成真实迁移链，再显式运行空校初始化；程序启动不得自动建表、自动生成演示业务数据或重置正式库。初始化会建立一个学校根组织、教师/教研室/学院/学校四类基础角色、学校管理员、计算保护记录、基础参数与字典，以及统一认证/学校数据中台/湘培直通车三类接口登记。三类接口初始状态均为 `NOT_CONNECTED`。

管理员临时密码从独立 secret 文件读取，不写进镜像、源码或业务审计。管理员首次登录必须自行改密。

## 2. 组织、账号与权限

组织层级为学校 → 二级学院 → 教研室。教师和教研室角色绑定教研室，学院负责人绑定学院，学校管理角色绑定学校根组织。角色支持批量授权与复制；数据范围由角色层级与当前组织关系动态计算，不逐用户复制数据范围。

组织或角色变化后，应立即验证旧会话、旧导出和旧下载是否失效。系统服务端执行范围校验，不能以隐藏菜单作为安全控制。

## 3. 基础配置与字典

可维护学校品牌、资质类别和到期提醒、统计口径说明、业务字典/状态显示、Excel 单批最大行数等受控参数。流程状态码和合法状态流转由服务端固定约束，管理员只能修改允许的显示名称，不能用配置把已归档状态改成可写状态。

关键配置变更必须填写原因，配置详情可查看操作人、时间、调整前值、调整后值和原因。

## 4. 周期、积分和考核规则

新周期建立后，规则按版本保存。修改既有制度时复制形成新版本，先选择代表教师/组织执行试算，确认后再启用。启用新版本不重写历史已确认积分或已归档考核。

学校真实上线前，必须使用 `acceptance/学校真实样本双轨比对模板.xlsx` 记录学校代表性真实样本，并通过 `scripts/dual_track_acceptance.py` 验证积分和考核人工/系统结果均达到 100% 一致，再由学校人员签认。

## 5. 接口配置

“配置完成”与“连接成功”严格区分。管理员可维护 HTTPS 地址、责任单位、鉴权模式、密钥环境变量名称、重试次数、同步频率和按数据类型的字段映射。页面不接收真实密钥值。

字段映射可以使用脱敏样本做本地转换验证；本地验证不会访问外部网络。学校数据中台还支持入站预览 → 错误定位 → 明确确认 → 正式主数据，以及 FULL 全量、INCREMENTAL 增量、人工拉取和定时计划的内部执行链。定时计划只有在真实 `CONNECTED`、已注册真实拉取适配器且管理员明确批准自动确认入库时才能启用；批准人失效、降权或接口掉线会自动停用计划。真实接口协议、网络和凭据未完成前连接状态必须保持 `NOT_CONNECTED`。

## 6. 统一待办与审计

统一待办覆盖资质审核/到期、教师考核、组织考核、核对申请和同步异常。办理后应检查待办是否随业务状态关闭或转交下一责任层级。

审计中心用于追查登录、配置、权限、资质、积分、考核、同步、导入导出等操作。关键业务审计与业务事务绑定；普通访问日志存储失败不得反转已经成功提交的业务响应。

## 7. 日常运维观察

运维页面只显示真实检查结果，不把采购阈值显示成“已通过”。每天关注数据库状态、worker 心跳、磁盘空间、最近备份和失败任务。备份文件存在不等于可恢复，必须定期在独立空实例做恢复演练。

## 8. 运行组成与监控

### 8.1 服务组成（`deploy/compose.yml`）

| 服务 | 作用 | 健康检查 | 说明 |
|---|---|---|---|
| `db` | MySQL 8.4（utf8mb4，UTC） | `mysqladmin ping`，每 5 秒 | 数据目录 `runtime/mysql`，仅内部网络可达 |
| `api` | 后端服务（端口 8000，仅内部网络） | `GET http://127.0.0.1:8000/api/health`，每 20 秒 | 只读根文件系统；附件目录 `runtime/files` 挂载到 `/var/lib/nondegree/files` |
| `worker` | 后台任务（导出、同步、拉取、定时计划） | `python -m app.healthcheck worker`，每 30 秒 | 约每 2 秒轮询；心跳写入 `runtime_state` 表 `worker` 行，超过 90 秒未更新判为不健康 |
| `frontend` | nginx（容器内 HTTPS 8443，对外映射 `ND_HTTPS_PORT`，默认 443） | 依赖 api 健康后启动 | 证书 `deploy/tls/fullchain.pem`、`privkey.pem`；`/api/` 反向代理到 api |
| `migrate` | 维护专用（迁移、初始化、检查） | — | `profiles: [maintenance]`，平时不运行 |

### 8.2 健康检查接口

`GET https://<学校域名>/api/health`（无需登录，维护期间也可访问）返回：

| 字段 | 正常值 | 异常含义 |
|---|---|---|
| `status` | `ok`（HTTP 200） | `not_ready`：数据库、迁移或初始化未就绪（HTTP 503） |
| `database.status` | `ok`（`engine: mysql`） | `unavailable` 数据库不可达；`unsupported` 非 MySQL 8.4 |
| `migration.status` | `ok` | `mismatch` 迁移版本与发布不符；`invalid` 非规范安装 |
| `initialization.status` | `ok` | `incomplete`：缺计算保护行、基础参数、学校根组织或四类角色 |
| `maintenance` | `OPEN` | `ACTIVE`：维护锁存在；`UNREADABLE`/`MISCONFIGURED`：维护目录异常 |
| `accepting_requests` | `true` | `false` 时业务接口返回 503“系统维护中，暂不受理业务请求” |

其他检查方式：

- 容器状态：`DC ps`（看 `healthy` / `unhealthy`）。
- 管理员页面：系统管理 → 运维与交付（`GET /api/operations`）显示数据库、后台任务进程心跳、存储剩余空间（GiB）、最近备份记录。
- 配置与结构自检：`DC run --rm --no-deps migrate python -m app.cli check`。

### 8.3 建议监控项与阈值

| 监控项 | 方法 | 告警条件 | 处置 |
|---|---|---|---|
| 网站可用性 | 外部探测 `/api/health` | 非 200 或超时 > 5 秒，连续 3 次 | 见第 11 节 11.1 |
| 容器健康 | `DC ps` | 任一服务 `unhealthy` 或反复重启 | 查对应服务日志 |
| worker 心跳 | 运维与交付页面 / `app.healthcheck worker` | 心跳 > 90 秒 | 见 11.3 |
| 磁盘空间 | `df -h`、运维页面剩余空间 | 剩余 < 20% 或 < 【待填】GiB | 转存过期备份、扩容 |
| 失败任务 | 导出与任务中心、接口中心按状态筛选 `FAILED`/`BLOCKED`；统一待办“同步异常” | 出现新的失败或阻断 | 见《接口异常处理说明》 |
| 安全审计 | 操作日志与安全审计，按结果“已拦截（DENIED）”筛选 | 同一账号短时间大量 403 或登录失败 | 核实人员，必要时停用账号 |
| 备份 | `runtime/backups/*.receipt.json` | 超过约定周期无新备份 | 执行第 10.1 节 |
| 证书 | 证书到期日 | 剩余 < 30 天 | 更换 `deploy/tls` 证书后 `DC restart frontend` |

## 9. 日志位置

| 日志 | 位置 / 查看方式 | 保留 | 内容 |
|---|---|---|---|
| 容器标准输出（api、worker、frontend、db） | `DC logs --since 1h api`（或 worker / frontend / db）；Docker json-file 驱动，存于 Docker 数据目录 | 每服务 20 MB × 5 个文件轮转（`compose.yml` logging 配置） | 启动信息、错误类型、请求编号；不含密码、SQL 参数和原始报文 |
| nginx 访问 / 错误日志 | `DC logs frontend`（`access_log /dev/stdout`、`error_log /dev/stderr`） | 同上 | HTTP 访问记录 |
| 业务审计与访问日志 | 数据库 `audit_events` 表；页面“操作日志与安全审计”，可按人员、模块、结果、时间检索并导出 | 随数据库长期保存 | 登录、访问、导出、权限调整、审核、计算、同步等；含调整前后值、原因、结果、请求编号 |
| 后台任务执行记录 | `task_attempts`、`sync_call_logs` 表；页面任务详情 / 逐笔结果 | 随数据库 | 每次执行结果与受控原因码 |
| 部署 / 维护记录 | `runtime/logs/maintenance-*.json`、`runtime/logs/last-deployment-smoke.json` | 不自动删除 | 每次备份 / 升级 / 恢复的操作与完成时间、HTTPS 冒烟结果 |
| 维护锁 | `runtime/maintenance/active` | 存在即表示维护中或上次维护中断 | 操作类型、阶段、开始时间、写服务是否已确认停止 |
| 备份回执 | `runtime/backups/<时间戳>.receipt.json` | 按学校保留策略 | 备份清单校验结果 |

排查技巧：用户报错时页面会显示“请求编号”（响应头 `X-Request-ID`），用 `DC logs api | grep <请求编号>` 及审计中的请求编号精确定位。

## 10. 备份与恢复

### 10.1 备份（`scripts/backup.sh`）

```bash
sudo bash scripts/backup.sh --allow-maintenance-window
```

执行过程（`scripts/deploy_control.py backup`）：建立维护锁 → **停止写服务（frontend、worker、api）** → `mysqldump --single-transaction` 导出并 gzip 校验 → 复制附件目录 `runtime/files` → 复制学校配置 `deploy/.env`（`school-config.env`，含私密配置，需妥善保管）→ 写安装来源证明、数据库逐表行摘要、备份元数据 → 生成并校验逐文件 SHA-256 清单 → 恢复原先运行的服务 → 解除维护锁。

- 备份目录：`runtime/backups/<UTC时间戳>-<随机串>/`（`database.sql.gz`、`files/`、`school-config.env`、`installation-provenance.json`、`database-reconciliation.json`、`backup-metadata.json` 及哈希清单），权限 0700/0600。
- 回执：`runtime/backups/<时间戳>.receipt.json`，状态 `HASH_VERIFIED_NOT_RESTORE_TESTED`——**只证明哈希完整，不证明可恢复**。
- 备份期间业务暂停（时长视数据量），须在维护窗口执行：【待填：学校批准的备份时间，如每日 02:00】。
- 异地保存：将备份目录复制到【待填：学校指定的备份存储】，保留策略【待填】。系统不自动删除历史备份。

### 10.2 恢复（`scripts/restore.sh`）

```bash
sudo bash scripts/restore.sh --into-empty-school <备份目录> [管理员用户名，默认 admin]
```

- **只能恢复到独立的空实例**（数据库无任何表），不能覆盖正在使用的库。
- 过程：校验备份清单与安装来源 → 启动空数据库 → 导入 SQL → 校验安装身份与逐表行摘要一致 → 恢复附件并逐文件比对哈希 → 迁移检查 → 清理会话并重置指定管理员临时密码（读取 `deploy/secrets/admin_password`）→ 断开外部接口、撤销自动计划、阻断未完成外部任务（`RESTORE_*` 原因码）→ 授权检查 → 启动服务与 HTTPS 冒烟。
- 恢复后**必须人工核对**：业务数据数量、附件抽查、考核归档校验码、真实账号登录；外部接口需管理员重新验证启用、重新批准定时计划后才恢复同步。确认无误后再切换访问地址。
- 建议每【待填：季度/半年】做一次恢复演练，并留存记录（可作为验收材料）。

### 10.3 业务数据移交导出（非灾备）

学校系统管理员在“表格导入中心 → 生成结构化移交包”（`POST /api/exports`，kind=handover）生成开放格式 ZIP，下载后用 `python3 scripts/verify_handover.py <zip文件>` 校验。该包用于数据迁移/移交，**不能**作为灾备恢复文件。详见《源代码与资料移交清单》。

## 11. 常见故障处置手册

| 编号 | 现象 | 可能原因 | 排查步骤 | 处置 |
|---|---|---|---|---|
| 11.1 | 网站打不开 | frontend 未运行、证书错误、端口被占用、防火墙 | `DC ps`；`DC logs frontend`；`curl -v https://<域名>/api/health` | 修复证书/端口后 `DC up -d --no-build frontend`；按严重故障流程通知供应商 |
| 11.2 | 页面提示“系统维护中，暂不受理业务请求”（503） | 维护锁 `runtime/maintenance/active` 存在（备份/升级/恢复进行中或中断） | 查看 `active` 文件内容（operation、stage、stop_confirmed）；确认是否有脚本正在执行 | 正在执行：等待完成。已中断：**不要直接删除锁文件**，先按 stage 判断失败点并查看 `runtime/logs`，确认数据库与附件状态无误后由部署负责人人工恢复；必要时从最近备份恢复到空实例 |
| 11.3 | 导出一直“排队中”、同步不执行 | worker 停止或心跳超时；处于维护 | 运维页面看心跳；`DC ps worker`；`DC logs --since 30m worker` | `DC restart worker`；仍失败记录请求编号联系供应商 |
| 11.4 | 健康检查 database `unavailable` | MySQL 停止、磁盘满、连接数满（上限 250） | `DC ps db`；`DC logs db`；`df -h` | 释放磁盘后 `DC up -d db`；连接数满时排查异常访问 |
| 11.5 | migration `mismatch` / `invalid` | 镜像与数据库迁移版本不一致；非规范安装 | 核对 `deploy/.env` 中镜像标签 | 回到与数据库匹配的镜像，或按第 12 节升级；禁止手工修改 `alembic_version` |
| 11.6 | initialization `incomplete` | 基础参数被破坏、四类角色缺失或学校根组织停用 | `DC run --rm --no-deps migrate python -m app.cli check` | 在“基础配置与字典”“组织、账号与权限”中修复；无法登录时联系供应商 |
| 11.7 | 用户无法登录 / 被锁定 | 密码错误次数过多、账号或组织停用、角色无效 | 审计中查“账号登录”模块记录 | 管理员重置临时密码或启用账号 |
| 11.8 | 用户“看不到数据”或 403 | 组织/角色层级不匹配、组织链中有停用组织、教师无工号 | 对照《权限配置说明》第 3 节核对 | 调整账号后让用户重新登录 |
| 11.9 | 提示“数据已被其他操作更新，请刷新核对”（409） | 乐观锁冲突，他人已修改 | — | 刷新后重新核对再提交，属正常保护 |
| 11.10 | 提示“数据库暂不可用或结果尚未确认” | 数据库瞬时故障 | 查 db 日志 | 先核对业务结果是否已生效，**不要直接重复提交** |
| 11.11 | 附件下载提示校验失败 | 存储文件被改动或损坏 | 比对 `runtime/files` 与备份 | 从备份恢复该附件，登记安全事件 |
| 11.12 | 接口同步失败 / 阻断 | 未联调、网络、证书、对方拒绝 | 接口中心任务与逐笔结果的原因码 | 按《接口异常处理说明》第 4–7 节 |
| 11.13 | 磁盘空间不足 | 备份、附件、日志增长 | `du -sh runtime/*` | 将旧备份转存后按保留策略清理；扩容；严禁删除 `runtime/mysql`、`runtime/files` |

严重故障（系统不可用、数据错误或疑似泄露）按《售后服务承诺书》通知供应商严重故障联系人：30 分钟内响应、2 小时内提供处置方案。处理全过程登记《问题整改清单》。

## 12. 版本升级流程

1. **准备**：获取供应商发布的 api、frontend 镜像（离线 `docker load` 或内网仓库）、发布说明和 SHA-256；确认是否含数据库迁移；先在测试/试运行实例验证。
2. **审批**：确定维护窗口并通知用户；确认最近一次备份可用。
3. **执行**：
   ```bash
   sudo bash scripts/upgrade.sh --allow-maintenance-window <api镜像:标签> <frontend镜像:标签>
   ```
   脚本依次：预检 → 校验安装来源 → 建立维护锁 → 停止写服务 → **自动完整备份** → 原子更新 `deploy/.env` 镜像标签 → 发布检查与 `alembic upgrade head` → 数据库授权与 `app.cli check` → 按 api、worker、frontend 顺序启动 → 校验运行镜像 → HTTPS 冒烟（写 `runtime/logs/last-deployment-smoke.json`）→ 解除维护锁。
4. **验证**：`/api/health` 为 ok；四类角色各抽一个账号登录核对菜单与数据；运维页面 worker 心跳正常；抽查一次导出。
5. **回退**：升级失败时维护锁保留、写服务保持停止。不得手工改回旧镜像直接连接已迁移的库；使用升级前自动生成的备份按 10.2 恢复到空实例后切换，或联系供应商处理。
6. **记录**：登记版本、时间、执行人、备份目录、验证结果。

## 13. 账号与权限日常管理

详见《权限配置说明》。日常要点：

| 事项 | 操作 | 注意 |
|---|---|---|
| 新教师入职 | 组织、账号与权限 → 新增账号（教师角色、所属教研室、工号必填） | 数据中台接通后，教师人事入站可更新姓名、职称、组织、在职状态 |
| 教师调岗 | 编辑账号所属组织 | 保存后旧会话立即失效，数据范围自动切换 |
| 人员离职 | 编辑账号，取消“启用” | 不删除账号，保留历史业务与审计 |
| 新建角色 | 角色与批量授权 → 复制角色 → 批量授权调整 | 不能授予超出本人的权限 |
| 调整某类人员权限 | 对其角色执行“批量授权” | 所有绑定账号一次生效 |
| 按人事表补建账号 | 账号与权限 → 账号管理 → “人事表有、还没账号 N 人” → 建账号（工号、姓名已带上，选教研室） | 建好后马上对上人事和授课记录，不用等下次同步 |
| 核对账号是否在职 | 账号管理的“人事状态”列和筛选：在职、不在职、人事表无此工号、管理账号 | “人事表无此工号”多为工号录错，先改工号再同步 |
| 系统管理员交接 | 先为新管理员开通管理员标志，再取消原管理员 | 系统阻止移除最后一位可用学校管理员 |
| 定期复核 | 每【待填】在“运维与交付”下载初始化配置与数据字典，核对账号角色 | 复核结果留档 |

## 14. 接口日常运维

| 频率 | 检查内容 | 位置 |
|---|---|---|
| 每日 | 接口连接状态是否仍为“连接证明有效”；同步/采集任务中的“处理失败”“未接通 / 已阻断”；统一待办“同步异常” | 统一认证与接口适配中心；统一待办 |
| 每日 | 数据中台定时计划最近错误、下次执行时间；入站预览中待确认批次 | 学校数据中台 → 定时计划 / 入站预览 |
| 每周 | 湘培直通车逐笔失败记录处理（单条补传 / 批量补传失败项） | 湘培直通车 → 逐笔结果 |
| 变更时 | 接口地址、证书、凭据、字段变化：先在草稿中修改并探测，通过后再启用；凭据只由服务器管理员配置环境变量，不在网页填写 | 接口适配中心 → 实施流程 / 验证与启用 |
| 凭据轮换 | 服务器管理员更新 `deploy/.env` 中对应环境变量后 `DC up -d --no-build api worker`，再在页面重新探测 | 服务器 |

**学校码表（代码对照）**：对接与同步 → 学校数据中台 → “代码对照（学校码表）”。从学校给的 Excel 复制两列（代码、名称）粘贴导入，页面就把代码显示成中文；**在职状态码表多一列“是否在职”（填是/否），必须在第一次同步教职工表之前导入**，否则人事表同步会提示“在职状态码表还没导入”且不入库。数据中台字段映射里当前状态 DQZTM 映射到 `hr_status_code`（文本），不要映射到 `active`。

**同步后的问题数**：对接与同步页的“本系统现有（条）”和“问题”两列。点问题数直接去处理：人事表跳到全校教师名册（只看有问题的），授课跳到“授课与学分”（只看需核对的），课程总库跳到没有学分的课程。

原因码含义与处置见《接口异常处理说明》。省平台正常版本升级、字段合理调整的适配，按《售后服务承诺书》第三条由供应商免费支持。
