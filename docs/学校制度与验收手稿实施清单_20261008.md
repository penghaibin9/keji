## 二、制度流程实现

### 项目与人次证据

- 复用既有项目、课程、班级和人员资料，新增项目期次及核算单元；公益项目允许明确的零收入。
- 高风险和补贴项目记录前置审核日期及依据，一般项目备案。核心变更要求重新备案并保存历史。
- 同期项目只采用模块式或人天式；参训明细先预检再整批确认。重复来源编号、仅换编号的重复核算单元均被拒绝。
- 多位教师共用参训单元，学院人次和项目实际收入不随教师数量重复累计。外聘教师可用稳定编号登记，但不进入个人积分认定。
- 人次依据包含签到、学时、全程参训、结业、重点群体、本校全日制学生、准毕业生例外和剔除原因。
- 结项核验方案、备案表、名册、考勤、学时、过程、考核和成果八类材料；补贴项目另有报送及专项凭证。
- 满意度低于85%登记整改期限；投诉、整改、结算、正式处理分别留痕。作废或否决须由有职责人员根据正式依据录入。
- 普通和补贴项目分别显示至少5年、10年保管要求；没有自动销毁。

### 个人积分

- 服务端按核算单元、人员、30人或50人标准班、层级、场景、岗位试算，展示公式与来源。
- 封顶有两种候选算法，缺少确认时不生成正式总分。当前支持学校明确选择“逐单元及汇总均保留两位、四舍五入”；其他精度解释需补充实现。
- 授课与辅助分列，校验项目总额、同一教师跨项目每日额度、备案细则和重复申报。
- 本人提交 → 院长初审 → 归口复审 → 分管副校长审批 → 教学秘书归档。执行本人回避、跨学院限制、越级拒绝、重复操作防护。
- 退回补正按学校确认的首次申报或补正日期处理；未确认时阻断再次提交。
- 归档保存计算快照及校验值，不能直接覆盖；更正单沿职责链审核并追加差额，保留原认定。
- 个人台账展示年度、历年、近五年、更正后积分和折算。辅助积分不折算教学课时。职称分先按年度汇总，再按确认范围与精度折算；缺失或冲突显示待确认。
- 近五年340分不自动拦截；双月报表取已归档数据，全校年度公示5个学校工作日并支持异议、处理、归档。
- 新旧规则同周期可能重复认定时阻断入账，历史汇总不会被推测为新制度明细。

### 学院年度考核

- 年度目标及财务依据独立登记，实际收入、人次取结项项目事实。
- 收入、人次、重点群体、成果、资金管理分别展示基础分、加扣分、封顶前后总分、否决依据和候选等级。
- 自评 → 职能部门及归口核验 → 委员会评分 → 公示5个学校工作日 → 异议处理 → 归档。
- 缺目标不记作零分或满分；两套考核关系、加分、评级、精度未确认时不得正式发布。平均积分须提供人数基准及依据。
- 作废项目的已归档积分未更正完毕时，阻断相应正式汇总。

### 数据、导出和兼容

- 增量新增6张业务表，保留原签名基线、旧规则和接口语义。迁移只从已验证基线向前升级，不自动破坏性回退。
- 附件校验、权限、中文明细导出、打印、待办、归档接入新业务；表格导出防止公式注入。
- 导出与打印属于系统办理记录，不替代学校尚未提供的正式制式表格。
- 原有两处前端未提交修改保留；本轮开发未提交、未推送、未部署。

## 四、正式使用前的待办和边界

1. 收齐学校书面解释：单次封顶及核算范围、两套考核关系、等级、加分叠加、比例和中间及最终精度、95%边界及成果去重、辅助日限额及重叠、职称范围和精度、年度人员基准、跨年及退回补正日期、校历。
2. 收齐正式备案表和认定表、学院辅助细则、职责名单、年度任务及人数基准、学校人工计算的脱敏样本。逐项配置比对，当前合成样本不是学校批准的计算结果。
3. 主要列表已分页；课程登记及个人积分申报的关联项目已补齐授权分页检索，教师参与项目改为数据库内精确成员查询。关联课程与其他部分候选仍取前200条，正式大量导入前须补齐剩余候选检索及规模验证。
4. 待验证：生产数据库引擎真实迁移、服务器发布和恢复演练、积分与年度考核完整多人浏览器走查、学校样本对照和签认。服务器专属测试因本机系统组件不兼容未验证；文件原件未逐页版式核验。
5. 真实迁移和发布须独立授权、备份及验证恢复路径。本轮没有执行这些操作。

首期未建设学员报名、在线签到、在线考试、实际视频学习时长采集；不代替财务收付款，不自动写人事系统，不把上传省平台报送凭证表述为接口已对接。
