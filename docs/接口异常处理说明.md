# 接口异常处理说明（统一认证 / 学校数据中台 / 湘培直通车）

> 对应采购条款：11.7（异常处理说明及问题处理清单）、11.4 与 11.8（自动重试不少于 3 次、单条/批量重试、人工补传、保留原失败记录）、11.9（重复识别与幂等）、4.4（自动重试、异常记录、人工补采）、4.6（异常编码和重试策略）。
> 依据代码：`backend/app/integration_diagnostics.py`（受控诊断码目录）、`backend/app/sync_policy.py`（重试预算与补传）、`backend/app/integrations.py`（出站逐笔同步、幂等键、退避）、`backend/app/inbound_sync.py` 与 `paged_inbound.py`（数据中台拉取）、`backend/app/adapters/*.py`（三类可配置适配器）、`backend/app/routes/sso.py`、`routes/integrations.py`、`routes/tasks.py`。
> 学校接口规范到位前，三类接口状态均为 `NOT_CONNECTED`（待对接），所有同步任务会被记为 `BLOCKED`（未接通/已阻断），这是预期行为而非故障。对方平台自定义的业务错误码需在联调时登记（见第 7 节）。

## 1. 总体原则

1. **不泄露**：任何错误只记录受控原因码、HTTP 状态和摘要（SHA-256），不记录原始报文、密钥、令牌或对方异常文本（`AdapterContractError` 只接受 `[A-Z0-9_]` 代码）。
2. **不丢失**：失败记录、执行尝试（`task_attempts`）、调用日志（`sync_call_logs`）只追加，不删除、不清零；补传后原失败记录仍可查询。
3. **不重复**：同一业务数据以“业务幂等键”识别；已成功的记录不会被再次发送；同一批内容重复提交复用原任务。
4. **不猜测**：配置或映射变化后，旧任务被阻断，必须用新配置重新生成；数据质量有错误的入站批次不能确认入库。
5. **有人负责**：所有人工重试、补传、确认入库、启停计划都需要学校系统管理员 + `sync.manage` 权限，并写审计（操作人、时间、原因）。

## 2. 重试策略（`sync_policy.py`）

| 项目 | 规则 |
|---|---|
| 自动重试次数 | 接口参数 `config.retry_count`，**默认 3**，允许 3–10；非法值会阻止执行（409“重试次数配置无效”）。含义是“首次调用之后的重试次数”，即一个周期最多调用 `1 + retry_count` 次（默认共 4 次） |
| 退避间隔 | 第 n 次失败后等待 `min(300, 2ⁿ)` 秒：2s、4s、8s、16s…最长 5 分钟（分页拉取为 `min(300, 2^min(n,8))`） |
| 达到上限 | 逐笔记录置 `FAILED`（处理失败），任务汇总置 `FAILED`，错误“存在失败或缺失同步项” |
| 人工重试 | 由管理员重新授权，开启**新的有界重试周期**：记录 `retry_base_attempt`（本周期起点），历史 `attempts` 不清零；仍使用原幂等键 |
| 不会自动重试的情况 | 接口未连接（`NOT_CONNECTED`）、适配器未部署（`ADAPTER_NOT_REGISTERED`）、配置或映射已变化、批次完整性校验失败、发起人权限失效——均直接置 `BLOCKED`，需人工处理原因后再操作 |
| 执行进程 | 后台 worker 每约 2 秒轮询，按租约（默认 300 秒）领取任务；维护期间不领取 |

## 3. 三类接口的处理链路

### 3.1 湘培直通车（出站，`province`）

1. 生成同步任务：`POST /api/connections/{id}/sync`（页面“实施人员补传”），每批 1–1000 条，每条须有业务唯一键（`business_key`/`id`/`external_key`），同批不得重复。
2. 按当前生效字段映射转换；缺少映射时拒绝发送空报文（409）。
3. 每条生成**业务幂等键** = 摘要（接口 + 数据类型 + 业务键 + 配置指纹 + 映射后报文）；同一接口同一数据类型下唯一。若已存在相同幂等键的记录，本批**引用原记录**（`reused_item_ids`）而不重复发送。
4. worker 发送前整批校验（数量、摘要、幂等键、配置指纹一致），任何不一致即 `BLOCKED`（`SYNC_BATCH_INTEGRITY_FAILED`），不产生外部副作用。
5. 逐条调用适配器 `send`，携带幂等键；对方须按登记的 `accepted_path/success_path` 判定受理，可选回执号 `receipt_id_path`。
6. 每次调用写 `sync_call_logs`：请求摘要、响应摘要、是否受理、对方返回码（仅登记过的错误码）、结果 SUCCESS/ERROR、受控原因码。

### 3.2 学校数据中台（入站，`middle`）

1. 人工拉取：`POST /api/connections/{id}/inbound/pull`（FULL 全量 / INCREMENTAL 增量）；定时计划：`/api/integration-schedules`（需管理员批准，可选“自动确认入库”）。
2. 拉取结果先进入**入站预览批次**（`inbound_batches` / `inbound_rows`），逐行做字段映射、格式校验、关联校验（工号对应账号、组织编码对应启用教研室、课程项目归属、来源更新时间不能倒退）。
3. 有任何错误行：任务置 `FAILED`（`DATA_QUALITY`），**保留预览但不写正式数据**；管理员在“入站预览”定位错误行，联系数据责任方修正后重新拉取。
4. 无错误：未批准自动确认的，任务 `DONE` 并提示“需人工确认”（`PREVIEW_REQUIRES_CONFIRMATION`）；管理员核对后 `POST /api/inbound-batches/{id}/confirm` 整批入库（整批在一个事务中，任一行失败全部回滚）。
5. 分页拉取：每页单独预览/确认，状态 `WAITING_CONFIRMATION`（本页待确认）；游标不推进、累计总量与源端不符会中止并报诊断码，不会静默漏页或重复入库。
6. 手工脱敏样本：`POST /api/connections/{id}/inbound/preview` 可上传样本走同一预览链（联调前验证）。
7. 已入库批次的撤销/恢复（4.4 回滚）：【整改中】入站预览详情正在增加“撤销本批入库”（`POST /api/inbound-batches/{id}/rollback`，按批次恢复入库前的主数据值；之后已被其他操作修改的数据拒绝撤销；审计永不删除）。以交付版本实际提供的功能为准；未提供时按《管理员操作手册》备份恢复流程处理。

### 3.3 学校统一认证（`sso`）

1. 登录：`GET /api/auth/sso/start` → 学校认证页 → `GET /api/auth/sso/callback`；一次性 state，过期或重复使用即拒绝。
2. 适配器验证票据/令牌并归一化身份（稳定标识、账号、工号、姓名、组织编码、在职状态、外部角色）。
3. 身份 → 本地账号映射；外部角色**不直接授权**，权限以本地角色/组织为准。
4. 每次失败写审计（模块 auth，结果 `DENIED`），用户看到中文提示，管理员凭请求编号核查。
5. 退出：`POST /api/auth/sso/logout` 清理本地会话及待处理认证请求，按学校配置跳转统一退出地址。

## 4. 诊断码目录（`integration_diagnostics.CATALOG`）与处置

页面“验证与启用”、连接健康检查、分页拉取等处返回统一结构：`code`（诊断码）、`stage`（类别）、`message`（中文说明）、`remedy`（处置建议）、`http_status`、`trace_id`（追踪编号）、`checked_at`。不在目录内的异常统一归为 `INTEGRATION_EXTERNAL_FAILURE`。

| 类别 stage | 诊断码 | 含义 | 运维/实施人员处置 | 责任方 |
|---|---|---|---|---|
| complete | VERIFIED | 真实协议与鉴权检查通过 | 继续核对身份/业务样本；不等于学校验收 | 双方 |
| deployment | ADAPTER_NOT_REGISTERED | 适配器尚未部署 | 部署人员安装适配器并重启 api、worker | 供应商 |
| deployment | CONNECTION_CONTEXT_NOT_PINNED | 网页配置与部署白名单（地址/凭据引用）不一致 | 核对正式地址与 `secret_env`；不得关闭地址校验 | 供应商 |
| credential | CREDENTIAL_MISSING | 服务器凭据未配置 | 服务器管理员通过安全渠道配置环境变量；**不要把密钥填入网页** | 学校运维 |
| protocol | PROBE_NOT_IMPLEMENTED | 适配器未实现探测 | 实施人员补全真实探测接口 | 供应商 |
| authentication | PROBE_REJECTED | 对方未确认身份验证成功 | 核对账号/密钥/签名；公开元数据或被拒绝的测试不能代替成功验证 | 双方 |
| unknown | PROBE_FAILED | 探测未完成 | 凭追踪编号查服务日志；不要重复粘贴密钥 | 供应商 |
| dns | UPSTREAM_DNS_FAILED / UPSTREAM_DNS_EMPTY | 无法解析或无可用地址 | 学校网络管理员核对 DNS、域名登记 | 学校网络 |
| network | UPSTREAM_ADDRESS_FORBIDDEN | 目标地址不在允许范围 | 学校内网域名需部署端明确放行（`ND_INTEGRATION_PRIVATE_HOSTS`）；禁止放行环回/元数据地址 | 供应商+学校 |
| tls | UPSTREAM_TLS_VERIFY_FAILED | 证书校验未通过 | 核对证书链、有效期、域名；**禁止关闭 TLS 验证** | 对方系统 |
| network | UPSTREAM_TIMEOUT | 对方响应超时 | 查网络、防火墙、对方负载；系统按重试策略自动重试 | 学校网络/对方 |
| network | UPSTREAM_TRANSPORT_ERROR | 无法建立安全连接 | 查端口、证书、对方服务状态 | 学校网络/对方 |
| http | UPSTREAM_HTTP_ERROR | 对方返回 HTTP 错误 | 结合 HTTP 状态：401/403 查授权，404 查路径，429 查限流，5xx 联系对方 | 对方系统 |
| response | UPSTREAM_JSON_INVALID | 返回不是有效 JSON | 核对响应格式；常见原因是请求被重定向到登录页 | 对方系统 |
| response | PROVINCE_RECEIPT_INVALID | 受理回执编号不符合保存契约 | 核对回执字段映射、类型和长度（≤128）；不截断、不记作成功 | 供应商+省平台 |
| pagination | PULL_COMPLETENESS_RULE_REQUIRED | 缺少分页结束判定 | 登记 has_more 字段或确认短页结束规则 | 数据中台 |
| pagination | PULL_CURSOR_NOT_ADVANCING | 分页游标没有推进 | 请数据责任方核对游标；系统不会漏页或重复入库 | 数据中台 |
| pagination | PULL_PAGE_LIMIT_EXCEEDED | 达到本次同步安全页数上限 | 核对总量和分页规则；保留已确认批次，勿盲目扩大限制 | 双方 |
| reconciliation | PULL_RESPONSE_TOTAL_MISMATCH | 源端总量与累计接收量不一致 | 核对快照与分页规则；本次同步不能视为完整 | 数据中台 |
| signature | SSO_ID_TOKEN_INVALID | 身份令牌验证未通过 | 核对签发方、客户端 ID、公钥（JWKS）和服务器时间 | 学校认证 |
| mapping | SSO_IDENTITY_ROOT_INVALID | 身份根路径不匹配 | 对照脱敏身份样本调整根路径后重新预览 | 供应商 |
| mapping | SSO_ACTIVE_RULE_MISSING | 账号启停规则未配置 | 登记真实启停字段和取值，不得猜测 | 学校认证 |
| identity | SSO_USERINFO_SUBJECT_MISMATCH | 令牌与用户信息主体不一致 | **停止上线**，请学校认证责任方核对主体映射 | 学校认证 |
| authentication | SSO_CAS_AUTHENTICATION_FAILED | CAS 票据验证失败 | 从测试登录入口重新获取一次性票据，不重复使用旧票据 | 双方 |
| configuration | INTEGRATION_CONFIG_INCOMPLETE | 配置校验尚未通过 | 先处理配置页列出的缺项 | 供应商 |
| protocol | INTEGRATION_EXTERNAL_FAILURE | 其他外部协议处理未完成 | 用追踪编号和受控错误码核查日志 | 供应商 |

## 5. 运行期原因码（任务、逐笔记录、执行尝试中可见）

| 原因码 | 出现位置 | 含义 | 处置 |
|---|---|---|---|
| NOT_CONNECTED | 任务/逐笔 `BLOCKED` | 接口未处于“连接证明有效” | 完成真实探测并启用后，用“重试/补传”重新授权；联调前属正常 |
| ADAPTER_NOT_REGISTERED | 任务 `BLOCKED` | 当前发布未注册该接口生产适配器 | 部署适配器后重试 |
| CONFIG_OR_APPROVAL_CHANGED | 拉取任务 `BLOCKED` | 接口配置变化或定时自动入库批准已撤销 | 核对配置，新建拉取任务或重新批准计划 |
| SYNC_BATCH_INTEGRITY_FAILED | 同步任务 `BLOCKED` | 批次明细、摘要或幂等键与原始不一致 | 不要重发；核对原批次后重新建批，并排查数据被改动原因 |
| EXECUTION_AUTHORIZATION_REVOKED | 同步任务 `BLOCKED` | 发起人账号或同步权限已失效 | 由在职管理员重新授权补传 |
| UPSTREAM_NOT_ACKNOWLEDGED | 逐笔 `RETRY/FAILED` | 对方未返回受理确认 | 自动重试；超限后核对对方受理规则 |
| AdapterContractError + 对方返回码 | 逐笔 error / 调用日志 response_code | 对方拒绝受理（如 `PROVINCE_UPSTREAM_REJECTED`）；若对方错误码已登记，则在调用日志“对方返回码”中显示 | 按登记的对方错误码含义处理（见第 7 节）；数据问题修正后人工补传 |
| DATA_QUALITY | 拉取任务 `FAILED` | 拉取数据有质量错误，已保留预览未入库 | 在入站预览查看错误行，联系数据责任方 |
| PULL_RESPONSE_NOT_ACKNOWLEDGED / PULL_PAYLOAD_INVALID / PULL_CURSOR_INVALID / PULL_COMPLETENESS_INVALID / PULL_INCOMPLETE_UNIT_REQUIRES_ADAPTER_PAGING | 拉取任务 | 数据中台响应不符合适配器契约 | 核对响应格式、分页设置；必要时改为分页适配器 |
| NO_CHANGES / AUTO_COMMITTED / PREVIEW_REQUIRES_CONFIRMATION / PAGE_PREVIEW / PAGE_COMMITTED | 执行尝试（成功类） | 无新增 / 已自动入库 / 待人工确认 / 本页待确认 / 本页已入库 | 按提示确认，无需排障 |
| RESTORE_REAPPROVAL_REQUIRED 等 RESTORE_* | 恢复后任务 | 从备份恢复后，原任务需重新批准/核验 | 管理员核对后重新授权 |

配置与探测阶段（保存/探测接口时）适配器还可能返回以下受控代码，均表示**配置或对方契约问题**，修正配置后重新探测即可：

- 通用配置：`ADAPTER_CONFIG_INVALID`、`ADAPTER_PATH_INVALID`、`AUTH_MODE_UNSUPPORTED`、`AUTH_CONFIG_INVALID`、`CREDENTIAL_*`、`SECRET_MATERIAL_FORBIDDEN_IN_CONFIG`（网页配置中出现了密钥）、`HMAC_*`、`SIGNATURE_ALGORITHM_INVALID`、`TIMESTAMP_MODE_INVALID`、`REQUEST_*`、`RESPONSE_PATH_*`、`PROBE_CONFIG_MISSING`、`PROBE_SUCCESS_RULE_REQUIRED`、`PROBE_EXPECTATION_FAILED`、`OAUTH2_*`。
- 传输层：`INVALID_PINNED_HTTPS_BASE`、`CROSS_ORIGIN_TARGET_FORBIDDEN`、`BASE_PATH_ESCAPE_FORBIDDEN`、`HTTP_METHOD_FORBIDDEN`、`REQUEST_TOO_LARGE`、`UPSTREAM_RESPONSE_TOO_LARGE`、`UPSTREAM_CONTENT_TYPE_INVALID`、`UPSTREAM_JSON_SHAPE_INVALID`。
- 数据中台：`PULL_DATA_TYPE_NOT_CONFIGURED`、`PULL_REQUEST_INVALID`、`PULL_RESPONSE_SPEC_INVALID`、`PULL_PAGING_INVALID`、`PULL_PAGE_EXCEEDS_LIMIT`、`PULL_WINDOW_EXCEEDS_LIMIT`、`PULL_RECORDS_INVALID`、`PULL_UPSTREAM_REJECTED`。
- 湘培直通车：`PROVINCE_DATA_TYPE_NOT_CONFIGURED`、`PROVINCE_SEND_INVALID`、`PROVINCE_RESPONSE_SPEC_INVALID`、`PROVINCE_ACCEPTANCE_RULE_MISSING`（未登记受理判定规则）、`PROVINCE_UPSTREAM_REJECTED`。
- 统一认证：`SSO_CONFIG_INVALID`、`SSO_PROTOCOL_UNSUPPORTED`、`SSO_*_PATH_MISSING`、`SSO_OIDC_METADATA_INVALID`、`SSO_TOKEN_RESPONSE_INVALID`、`SSO_TOKEN_TYPE_INVALID`、`SSO_STATE_MISSING`、`SSO_CODE_MISSING`、`SSO_CAS_TICKET_MISSING`、`SSO_CAS_XML_INVALID`、`SSO_VERIFY_REJECTED`、`SSO_IDENTITY_FIELDS_INVALID`、`SSO_ORG_MAP_INVALID`、`SSO_IDENTITY_INVALID`、`SSO_STABLE_IDENTITY_MISSING`、`SSO_ACTIVE_MUST_BE_BOOL`、`SSO_BROWSER_SECRET_FORBIDDEN`。

说明：运行期逐笔同步中，若原因码不在第 4 节目录内，系统只记录通用类型（`AdapterContractError` / `INTEGRATION_EXTERNAL_FAILURE`）以防泄露，详细原因请凭“请求编号/追踪编号”查 api、worker 容器日志。

## 6. 统一认证登录失败提示（用户可见）与处置

| 用户看到的提示 | 原因 | 处置 |
|---|---|---|
| 学校统一认证尚未完成真实联调或当前连接不可用（503） | sso 接口未处于连接证明有效 | 用本地账号登录；管理员完成联调启用 |
| 当前发布未安装学校统一认证生产适配器（503） | 未部署适配器 | 部署适配器 |
| 学校统一认证暂不可用，请稍后重试（503） | 认证服务不可达 | 检查网络/对方服务 |
| 统一认证请求已过期或已使用，请重新登录（401） | state 过期或重放 | 重新从登录页发起 |
| 统一认证已通过，但本系统尚未建立该人员账号映射（403） | 无对应本地账号 | 管理员新建账号或核对工号/账号映射 |
| 统一认证身份同时匹配多个本地账号（409） | 映射歧义 | 管理员清理重复账号/工号 |
| 学校稳定身份与当前工号/账号字段指向不同本地人员，禁止自动改绑（409） | 身份冲突 | 管理员核实人员后人工处理 |
| 账号组织或授权范围不可用，请联系管理员 | 本地账号停用/组织停用/角色无效 | 管理员核对账号、角色、组织 |

## 7. 重试、补传与重复识别操作

所有操作入口：系统管理 → 统一认证与接口适配中心 → 选择接口 → “同步任务 / 逐笔结果 / 采集任务 / 入站预览 / 定时计划”分区。均需填写原因，写入审计。

| 操作 | 页面入口 | 接口 | 作用范围 | 说明 |
|---|---|---|---|---|
| 单条重试 | 逐笔结果 → “回执 / 单条补传” → “单条补传” | `POST /api/sync-items/{id}/retry` | 1 条 `FAILED/RETRY/BLOCKED` 记录 | 校验记录版本；成功记录不会重发 |
| 批量重试 | 同步任务详情 → “批量补传失败项” | `POST /api/sync-tasks/{id}/retry-failed` | 该任务全部失败/阻断记录 | 原任务被执行中（租约未到期）时拒绝 |
| 任务重试 | 采集任务 / 导出与任务中心 → 任务详情 → “留痕重试” | `POST /api/tasks/{id}/retry` | sync：等同批量补传；inbound_pull：重新授权拉取 | 仅 `FAILED/BLOCKED` 可重试；配置已变化须新建任务 |
| 人工补传 | 同步任务 → “实施人员补传” | `POST /api/connections/{id}/sync` | 1–1000 条 | 用于修正后的数据重新上报；相同内容自动识别为已有记录 |
| 人工补采 | 采集任务 → “全量 / 增量拉取”，或入站预览上传脱敏样本 | `POST /api/connections/{id}/inbound/pull`、`/inbound/preview` | 指定数据类型 | 先预览后确认 |
| 确认入库 | 入站预览 → “查看 / 确认” → “确认写入主数据”（分页为“核对并确认当前页”） | `POST /api/inbound-batches/{id}/confirm` | 整批 | 只能确认本人生成、无错误行、配置未变化的批次 |
| 查看证据 | 同步任务 → 证据 | `GET /api/sync-tasks/{id}/evidence` | 任务 | 逐笔状态、调用摘要，用于联调记录 |

重复识别与幂等（11.9）：

- **写请求幂等**：所有写接口必须带 `Idempotency-Key`；同一操作人同一编号重复提交返回原结果，不同内容复用编号返回 409。
- **同步批次幂等**：任务键 = 摘要（接口 + 类型 + 全部记录 + 配置指纹），同一批重复提交返回原任务。
- **逐笔幂等**：业务幂等键唯一约束（`sync_items` 上 connection_id + data_type + idempotency_key 唯一），重复记录引用原记录、不重复发送；补传沿用原幂等键并传给对方，供对方去重。
- **入站幂等**：培训台账以 `external_key` 唯一；同编号同内容视为“未变化”，同编号不同内容拒绝入库并提示先在台账核对；教师人事以 `source_updated_at` 防止旧数据覆盖新数据。
