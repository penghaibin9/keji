## 四、维护和健康语义

升级只有最外层持有flock；内嵌备份没有EXIT恢复业务逻辑。持久`runtime/maintenance/active`在失败后保留。普通API看到它返回503；`/api/health`允许探测数据库/迁移/初始化就绪，维护时可以HTTP200但明确`accepting_requests:false`，不代表业务入口已经打开。

备份前停止写服务，数据库dump与原附件复制后逐文件hash并fsync。备份成功只标记HASH_VERIFIED_NOT_RESTORE_TESTED。单独备份只恢复之前实际运行的服务集合。升级失败不直接逆向降级未知数据库。不能确认停止（例如Docker守护进程不可用）会记录`stop_confirmed:false, manual_isolation_required:true`；仍需现场隔离，不谎报服务已停止。

仅在迁移、授权、一致性检查、新镜像核对、HTTPS资源与就绪探测完成后清除维护标记。该探测不登录、不修改业务，不替代授权业务冒烟。**缺失的worker必须补维护期间暂停领取/执行业务任务并保持心跳的实现与测试；仅挂载标记目录不能证明worker已受控。**

3. ordinary access日志降级与关键业务审计分开。核心audit/workflow缺件，现有业务函数审计异常能回滚不代表全系统审计已通过。
4. 本轮没有变更规则公式、资质周期判定、金额人次粒度、机构考核、接口协议；不把推测的学校制度自动落为规则。
5. 新P0测试夹具只在tests使用，不是生产实现。不能把测试包内SQLite建表、合成HTTP服务或DockerFaultDriver复制进正式认证/worker。
