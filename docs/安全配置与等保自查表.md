# 安全配置与等保自查表

核对日期：2026-10-12。范围为当前源码和正式部署模板的只读核对，未连接学校服务器，未查看真实数据库或凭据。下表用于学校信息中心确定整改和运维责任；“程序具备”指源码证据，不代表学校现网已生效，也不等同于正式等级保护测评结论。

## 当前核对结果

密码长度和首次改密、登录失败锁定、安全会话、当前授权复检、关键业务审计、文件校验已有代码。需学校明确或补证据的主要事项是密码有效期政策、至少六个月日志留存、备份加密和异地副本、静态网页统一安全响应头、个人信息授权及运维责任。

现行《中华人民共和国网络安全法》第二十三条要求相关网络日志留存不少于六个月，并提出数据分类、重要数据备份和加密措施。本次核对的是 2025 年修正版现行全文，使用其当前条次。[中央网信办公布的网络安全法全文](https://www.cac.gov.cn/2025-12/29/c_1768735112911946.htm)

## 六个月日志保存方案（建议，尚未实施）

学校信息中心提供集中日志服务器或受控日志平台。接入数据库/应用/网关运行日志与关键审计、访问审计事件，保留操作时间、系统身份、结果、来源或请求追踪编号。采集链路使用安全连接，存储按最小权限管理，避免保存认证票据、会话、密码和个人业务正文。

保存策略按日归档，按“当前日期减六个日历月”确定最低保留边界；可由学校设置更长的保存期。不能把固定文件份数当成六个月，也不应机械地用 180 天替代六个日历月。容量按实测日均及峰值增长估算，再留学校批准的余量。容器目前 20 兆字节乘 5 的轮转只作为短期缓冲，集中采集须及时，不能等被覆盖后才备份。

至少定期检查采集连续性、时间同步、磁盘空间、最近日志和留存边界最早日志是否能检索；出现采集停滞、审计写入失败或空间不足时告警给学校指定负责人。日志库采用独立受限账户，保留异地或防篡改副本及检查记录，清理只在学校批准策略下进行。

到校验收提供集中平台配置导出、采集与告警检查、检索和恢复样本。新建学校系统运行不足六个月时，提供既定保存策略、容量及首期运行记录，再在累计满期后核验边界，不伪造历史日志。
