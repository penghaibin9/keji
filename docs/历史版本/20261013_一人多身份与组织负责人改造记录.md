# 一人多身份与组织负责人改造记录（2026-10-13）

分支：`claude/multi-role-20261013`，基于 `claude/teaching-credit-review`（dfd4a69）。

## 为什么改

- 账号只能存一个角色、一个组织，兼任（教师 + 教研室负责人 + 学院负责人）的人没法保存。
- 学校 733 位老师全是普通教师，没有负责人时教师考核卡在教研室环节、授课认定没人能认定，学校也不能代办。

## 怎么改

1. **不改数据库结构。** 学校服务器已上线，这次不加迁移。账号主身份仍是 `users.role_id/org_id`；兼任身份存在 `settings` 表 `account_identities` 一行（和授课认定存在 `SocialResource` 的做法一样）。该行不在“规则与配置”里显示。
2. **当前身份用签名 Cookie 选定**（做法同演示身份切换）：签名绑定会话、校验码和账号授权版本；切换时刷新校验码；签名失效回到主身份；被移除的身份要求重新登录。每次请求仍只有一个当前身份，原来按角色分支的业务代码不动。
3. **组织页设负责人**：`POST /api/organizations/{id}/heads`、`/heads/remove`、`GET /head-candidates`；只能从本组织在职、有工号的老师里选，添加的是兼任身份。
4. **缺位上交**（`identities.stage_handler`）：教研室无可用负责人 → 学院代办；学院也无 → 学校代办；学院无 → 学校代办。用于教师考核确认/退回、待办、授课认定。办理轨迹 `after.handling` 记“代缺位……办理”“同一人连审”。
5. **其他**：账号弹窗先选角色再按层级列组织；账号列表显示兼任身份；`POST /api/users/{id}/unlock` 解锁不改密码；审计在兼任身份下记 `acting_identity`。

## 已知边界

- 考核列表“本级待处理”快捷筛选仍按角色层级取状态，不含代办事项；代办事项在“统一待办”里出现。
- 人事同步只移动主身份（教师）的教研室；调岗会标“授权待确认”，管理员确认时在同一弹窗核对兼任身份。
- 兼任身份不能是学校管理员；系统管理员标记仍只认主身份为学校角色的账号。
