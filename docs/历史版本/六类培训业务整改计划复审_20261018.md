## 一、总体结论

方向是对的，但这份计划太大、顺序也不对，还把 AI 生成的图片当成了需求来源。

1. **最急的事计划里没写：先把现有改动保存进 git。** 10/17 下午到今天，Codex 做的审批中心、四角色切换、四角色走查修复和六页还原，全部还没提交，一共 82 个文件。"保存代码"时，Codex 只是在 `代码备份/` 里打了一个 zip，这违反了仓库 AGENTS.md 里"改完就 commit、不建备份目录"的规定。另外，驾驶舱改版在另一个分支 `codex/leader-cockpit-design-20261017` 上，也改了 `app.js`、`index.html`、`business.py`，以后合并时一定会冲突。应该先拆开提交，再开始新的整改。
2. **"六张原型"不是学校给的，是 Codex 自己生成的效果图。** 这些图是根据你给的老师截图做出来的。里面的"育训融合、智慧助老、学习型社区、乡村振兴"四类课程主题，学校的三份文件和源码里都找不到出处。它们原本是那位老师截图里资源成果的分类，不是课程主题。你在 Codex 的选项卡里点过"增加独立主题，多选（推荐）"，但这只能算你的设计偏好，不能算学校规则。计划里写的"已确认方案"应该改成"待学校确认"，至少不能让它进入统计口径。原型图只能用来定样式，字段要以学校文件和上级报表为准。计划第一节已经写了这条原则，但第二节又把原型图上的内容当成了字段需求。
3. **范围过大，属于过度设计。** 计划要求把六类业务的所有入口、所有阶段都重新审一遍，还包括双月报送、公示、异议、回避、导入、接口、归档等。可这些流程前几轮已经做过并走查过：审批中心改造、四角色真实输入走查、退回补正复验，证据都在 `docs/历史版本/` 里。第一步"建立完整对照清单、不留遗漏"没有尽头，很可能又产出一大批报告，页面却没改多少。建议只保留真正的缺陷和缺口，见第四节。
4. **顺序要调整。** 现在的顺序是"清单 → 数据完整性 → 字段 → 流程 → 图片 → 页面还原 → 验收"，但页面还原其实已经做完了（只是没提交）。正确的顺序应该是：先保存现有改动，再修数据覆盖缺陷，然后纠正还原中做偏的地方，最后按需要补字段。

## 三、培训项目那次还原，具体哪里改偏了

代码在 `frontend/training-workspace.js`（共 82 行），截图对比的是 `final-01-projects.png` 和原型图 `01-培训项目管理.png`。

1. **四个角色共用了学校管理端的原型。** 原型画的是学校管理端，但现在教师、教研室、学院也都换成了同一个图文列表。教师原来有"我的角色"列和"上报资料待学院完善"提示，学院和教研室有昨天刚逐页优化好的表格，这些都被收进了底部折叠的"完整清单与统计口径"里（`social-training.js:230-236`）。这相当于把 10/17 二级学院端、教研室端的优化成果藏了起来。
2. **每条记录都配了假图片。** 后端的项目、基地、成果和师资根本没有封面字段，`cover_url` 和 `photo_url` 都不存在，只有超星线上课程有封面。所以现在页面上全部是生成的示意图：名称里带"茶"字的项目用茶室图，其他项目一律用**基地图**，成果也用茶室图或基地图（`training-workspace.js:16`）。原型对没有封面的记录用的是一个文件图标（比如课程图里的"农产品包装设计"），所以这里应该用中性图标，而不是挂一张看起来像真实照片的图片。
3. **右侧详情的指标和原型不一致，而且不分阶段。** 原型显示的是总学时、**有效人次、到账收入、课程门数**。还原后改成了总学时、预计人次、预计收入、项目期次，并且已结项的项目也显示"预计"数据（第 50 行）。期次的文字在截图里被截断了（"退回复验—期"）。下方的"预计收入 0 元"也被固定在底部的按钮压住了一半。
4. **原型里有"项目材料"区，还原后没有。** 原型有"培训方案、参训与结业材料"入口，还有一个按阶段变化的主按钮"办理结项"。还原后只剩一个通用的"查看 / 办理"按钮。
5. **进度条有两处错误。** 已结项的项目，第 4 步仍然显示为"进行中"，没有显示为已完成（第 48-49 行把 FILED、CLOSE_*、CLOSED 都算作阶段 3）。另外原型是打勾表示已完成，现在用的是数字圆点。
6. **"待审批"页签把草稿和退回的项目也算进去了**（第 34 行）。草稿还没提交，不应该出现在待审批里。
7. **学院和状态筛选只在前端当前页里过滤**，而且按学院名称匹配，没有用学院编号。一旦设置了筛选条件，翻页按钮就会隐藏（第 80 行）。目前每页 200 条，实际影响不大，但计划第六步要求筛选在分页前执行，这一点还原并没有做到。
8. **课程页（顺带发现）**：页签是"视频课程 / 培训包 / 一人一技"，和上方的"培训包、一人一技"勾选框重复了。原型上是四类主题页签，计划和还原在这一点上互相矛盾。
9. **师资的状态是写死的**：校内一律显示"已认定"，外聘一律显示"备案有效"，并不读取真实状态和有效期（第 25 行）。

还原记录 `design-qa.md` 里自己也写了：基地和师资在非空数据下没有用浏览器验证过，"结果"并不等于逐项一致。

## 四、建议的执行顺序（替代原来的七步）

1. **保存现状**：把 82 个未提交文件按主题拆成几次提交（审批中心、角色切换、走查修复、六页还原），新开一个 `codex/training-six-pages-20261018` 分支。另外，先决定驾驶舱分支和这条线谁先合并。
2. **修数据覆盖问题**：基地和成果修改改成"只更新提交了的字段"（`exclude_unset`），前端表单补上用途、设立日期、共建单位、级别。补测试，确认修改一项不会动到其他字段，并确认校外基地可以正常保存。
3. **纠正还原中做偏的地方**：先给教师、教研室、学院恢复原来的列表，图文布局只给学校管理端用；把假图片换成图标；详情按阶段显示预计值或实际值；补上项目材料区和按阶段变化的主按钮；修正进度条和"待审批"页签。
4. **按学校文件补字段**：只补办法第十一条、第十三条和第三十条明确要求的内容（项目级一人一技、重点群体、零收入说明、结项专项材料、双月签字依据），封面图片设为选填。
5. **四类主题和计分口径**：列入"待学校确认"。拿到答案之前不改代码，也不写进统计口径。
6. **只验收这次改动涉及的部分**：把这一轮改过的地方用浏览器走一遍。不要再对全系统重新做一次全量走查。

计划第四节"待学校确认事项"写得很好，可以直接整理后发给学校。
