## 一、结项后上报资料更正

验证已结项核心申报资料不能直接覆盖，教师不能代替学院更正上报资料。由学院正常接口将合成项目上报总学时从2改为3，项目仍为已结项，结项核验记录、原积分认定快照和原始积分分录均保留。

本轮发现一个缺陷：只提交总学时，接口会把未提交的受众群体、服务面向、教学方式等字段按模型默认值清空。缺陷只影响本次合成项目的试验字段，没有影响学校台账。

修复：backend/app/routes/social.py 的 project_report_info 只合并本次实际提交的上报字段。未提交的字段保持原值；明确传空列表或数字零仍按用户输入保存。系统自动留存更正人、更正日期和办理依据。

用本轮已保存基线通过正常接口恢复被试验清空的合成字段后，在同一项目复验修复：只更正总学时，其他上报字段和结项资料保持不变；旧版本保存被拒绝。没有恢复或覆盖整个运行数据库。

新增隔离回归验证了未提交字段保留、明确清空、数字零、版本冲突以及原归档认定快照不变。

## 二、第一张积分追加更正：增加0.20分

1. 教师为原认定创建增加0.30分的合成更正草稿；缺附件时不能提交。
2. 上传合成佐证后提交。同一原认定有未完成更正时，另建更正被拒绝；教师自审、分管越级审核被拒绝。
3. 学院退回补正，教师在同一张更正单上将差额修订为增加0.20分并补充依据；旧版本保存被拒绝。
4. 重提后依次通过学院、归口、分管、秘书归档。归档前每个阶段均核对账本仍为1.00分。
5. 归档后净额为1.20分。同一提交请求重放、同一归档请求重放没有重复入账；使用新请求重复归档、归档后作废或重提均被拒绝。

## 三、第二张合法后续更正：核减0.10分

1. 第一张更正归档后，新建独立的核减0.10分合成更正。两项差额都为零的申请被拒绝。
2. 创建请求重放返回同一记录，没有产生第二张草稿。
3. 学院通过后由归口退回，教师保留原更正单补充依据，再重新走学院、归口、分管和秘书审核。
4. 该单归档前账本保持1.20分；归档后为1.10分，重复归档被拒绝。

两次差额均为明确标记的合成决定，仅测试追加记账机制，不把上报总学时的修改自动换算成积分，也不代表学校真实认定。
