# 二三级填写页面统一整改规划

日期：2026年10月13日。用途：配合《对接与规则前端审计及整改报告》指导后续界面整改。本次仅规划和制作交互示意，未实施产品代码修改。

## 一 用户会感受到什么

1. 已有姓名、学院、项目、周期和已确认接口资料自动带出；不重复抄写。
2. 简单登记一页完成，复杂申请按业务内容分段；不把所有字段塞进长弹窗。
3. 找人用姓名或工号搜索，能看到学院、身份及是否可办理；不用记账号。
4. 填错时直接指出哪一项，已经填好的内容保留；没有可选项时说明原因和办理入口。
5. 暂时缺少材料或学校未确认的口径可以保存草稿；正式提交、启用和入账仍执行原业务校验。
6. 保存后看得到保存结果和下一步；进入详情能继续编辑允许修改的内容。

现有中台数据、账号、历史积分、已归档结果和已确认配置属于必须保护的内容。界面整改不自动清空数据、重建接入或重算历史。涉及后台缺陷的修复另按审计编号验证。

## 三 各类页面采用同一套办理方式

| 类型 | 适用页面与动作 | 二级页面 | 三级填写或办理页 |
|---|---|---|---|
| 基础资料登记 | 课程、基地、成果、课程资源、通知、普通字典项 | 列表、状态、检索、详情及新增入口 | 短表单，合理默认值，明确必填与选填，保存后返回原位置 |
| 长业务申报 | 培训项目、结项、学院年度自评 | 当前事项、缺项、办理阶段和下一步 | 按基本资料、业务依据、材料、核对分段；段数依业务，不强制全部四步 |
| 教师个人办理 | 资质申报、积分申报、退回补正、个人异议 | 本人记录、退回原因及办理入口 | 身份自动带出，关联项目检索，原材料保留，失败只补传失败部分 |
| 审批与更正 | 审核、退回、归档、积分核对、追加更正 | 事实、依据、异常、材料集中展示 | 一次确认；退回和更正必须写真实原因；更正显示原值、差额及结果 |
| 制度与计算规则 | 周期、制度口径、教师规则、组织规则、样本试算、规则复制 | 适用范围、版本、状态、待确认项 | 范围先选，参数按用途分类，试算与启用分开，缺项可定位 |
| 人员及权限 | 账号、组织负责人、兼任身份、角色授权、社会培训职责 | 人员与组织关系、职责缺口 | 姓名工号检索，现有选择完整回显，显示增减与影响，后台仍核验权限 |
| 导入与同步 | 台账、参训明细、课程导入、码表、入站批次 | 任务进度、可处理错误、历史记录 | 选类型或对象、上传、预检、核对、确认；支持返回修改且保留已填内容 |
| 已接通接口维护 | 统一登录、中台、省平台、同步计划 | 当前可用性、最近结果、错误处理、计划 | 日常动作简短；协议、鉴权、映射及原始参数进入实施人员高级设置 |
| 统计与输出 | 计算范围选择、汇总、公示、导出、打印 | 当前范围和可用结果 | 明确数据范围、预览数量或样例、确认后执行，显示实际结果 |
| 安全及运维 | 密码、解锁、凭据元数据、备份恢复、账号停用 | 现状和影响范围 | 独立明确确认，不套用“自动提交”；本人验证及高风险授权继续保留 |

以上覆盖现有主页面进入的填写动作。新增表单须先选所属类型，不另造一套按钮、错误和保存方式。界面不能提供后台没有支持的草稿、撤销或更改能力；确需补齐时先明确服务端规则再实现。

## 四 统一填写规范

### 进入表单前

- 标题使用“新建培训项目”“补正积分申报”等业务动作；显示当前对象和返回入口。
- 缺权限、无周期、无可选项目等前置条件，进入前说明清楚；不能打开一张注定填不完的空表。
- 沿用原列表的检索、页码和选择，关闭或办完返回原位置。
- 短表单用现有弹窗；复杂表单采用完整编辑页或明确分段，避免多层弹窗和多重滚动。

### 填写时

- 中文标签放在输入框上方，字段同类同名；选填项直接标“选填”。提示说明“填什么、哪里取得”，不重复标题。
- 已有资料带出并注明来源；只有学校正式确认的规则可默认采用。零收入、零上限等有业务意义的零值必须保留。
- 人、学院、项目、周期和本平台业务字段优先选择或检索；大量候选采用分页检索，不能只读前200条后当成全部。
- 日期、金额、人次使用对应控件。相关日期一起说明；周期、校历、规则生效日期保持独立语义。
- 选项决定后续字段是否需要填写，例如三等制才显示三等门槛。切换选项不能静默删除已有有效内容。
- 长表单每段只处理一个业务主题；可返回修改；已填内容在本次流程中保留。
- 不把“保存草稿”当成虚假成功。正式持久化成功后才显示已保存；敏感业务资料不私自放入浏览器长期存储。

### 校验与失败恢复

- 在点击下一步或保存时校验，不在用户每输入一个字时弹错。
- 顶部汇总问题，字段旁给出具体原因和纠正方法；点击问题可到对应字段。
- 区分格式错误、学校业务条件未满足、权限不足、网络失败和版本冲突，分别给出处理入口。
- 网络结果不明时先回读，不能自动重复提交。版本冲突显示变化并保留当前输入，不能刷新后丢掉人工修改。
- 文件逐份显示状态，上传失败只重试失败项；上传格式、大小及数量以后台实际限制为准。

### 保存和提交

- 一个主动作，按业务明确命名：保存草稿、提交审批、确认启用、归档入账等。
- 保存草稿与正式启用分开；适当的常规说明可预填，但不代替审核人意见、学校依据或本人确认。
- 重要提交前显示关键摘要，可就地返回修改，不要求全部重填。
- 成功后说明“保存了什么、处于哪一步、下一步谁处理”；不能把已保存写成已审核。
- 调整已有配置或授权时，只改变本次明确修改的内容，保存后回读核对。

## 五 五个可交互示意的含义

| 示意 | 改后操作 | 仍保留的要求 |
|---|---|---|
| 规则填写 | 范围、计分口径、校历、核对；随时存草稿 | 学校未确认的政策不能自动启用；已生效版本保护 |
| 项目申报 | 基本资料、安排与材料、核对提交 | 正式申报的必要字段、材料和审批不删 |
| 选择审批人 | 搜索姓名或工号、选择人员、核对变更 | 组织范围、有效身份、职责及本人回避仍检查 |
| 中台维护 | 看已有数据和异常；字段维护选择中文业务字段 | 认证配置不被重置；保存草稿与正式发布区分 |
| 统一登录 | 试一次、看匹配结果、确认开通 | 真实认证、工号绑定、回调验证和本地备用登录保留 |

示意中的人员、年度及操作结果均用于说明，不调用真实登录、同步、保存或审批。它不是已完成整改的产品版本。

## 六 实施顺序与验收门槛

第一批：统一表单错误、返回、选择器和保存反馈；同步修复审计报告中可能改变既有配置、漏掉人员和成果的缺陷。

第二批：规则填写、项目申报、审批职责、统一登录维护和中台字段维护五类高频页面，按照示意和后台实际能力实施。

第三批：把同类型标准应用到覆盖清单其余入口；每个入口分别记录已改、已测、待测，不以一个示范页面代替全系统完成。

逐页验收至少覆盖：

1. 正常新增、编辑、返回继续、关闭重开、刷新回读。
2. 缺必填、日期冲突、显式零值、无可选项、大量候选、网络失败、重复点击和版本冲突。
3. 无权限、兼任身份、本人回避、已归档不可改及附件归属。
4. 已有中台认证参数、账号、材料、审批历史和正式结果没有连带变化。
5. 桌面与390像素宽度操作，字段和按钮完整可见；键盘可以进入、返回、定位错误；焦点不被弹窗困住。
6. 若用草稿或进度提示，必须有后台回读证据；若称为真实接通，必须有学校实际接口与账号证据。

保留现有学校标识、导航分类和已确认业务词语。具体页面简化不能通过取消校验、权限或留痕实现。

## 七 设计依据与证据说明

本规划参考中后台与公共服务表单的成熟做法，按本项目业务选用，不声称已经取得某项界面合规认证，也不要求更换前端技术框架。

- 标签采用用户能理解的词语，结合上下文、提示和检索减少猜测。参考 [Ant Design（蚂蚁设计体系）的数据输入规范](https://ant.design/docs/spec/data-entry/)。
- 重要提交前显示已填摘要，允许回到对应内容修改并保留原输入。参考 [英国政府设计体系的提交前核对模式](https://design-system.service.gov.uk/patterns/check-answers/)。
- 校验失败保留输入，使用具体字段错误与错误汇总帮助恢复。参考 [英国政府设计体系的表单错误恢复模式](https://design-system.service.gov.uk/patterns/validation/)。

本地实拍和交互示意位于本会话的可视化目录。截图仅反映隔离样本及拍摄时页面；本报告不据此判断学校线上配置是否完整。学校线上已经取到中台数据这一背景继续按用户确认保留。

## 八 交互示意验证结果

已在真实浏览器中检查五类示意的主要操作：规则分段、缺项提示、条件字段、保存草稿和核对；项目填写、材料回显、零收入保留和提交结果；姓名及工号检索、跨检索保留已选人员；中台中文字段选择；统一登录试用与一次确认。示意不会调用学校或本地业务接口。

桌面预览和截图已检查。390像素宽度下已进行浏览器布局测量，未发现控件横向溢出；完整手机长截图未能取得可用结果，因此不宣称已完成完整移动端视觉验收。浏览器记录未发现示意脚本错误。

这些检查验证的是规划示意，不替代将来对真实产品的保存、权限、并发、数据回读和学校接口验收。
