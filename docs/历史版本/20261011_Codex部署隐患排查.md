## P0 阻断上线

### 1. `开始部署.sh` 是本机受限演示流程，老师无法通过内网访问
- **位置**：`delivery/manage.py:112-117`、`delivery/manage.py:132-134`、`delivery/manage.py:87-88`
- **证据**：
  ```python
  text=env.read_text().replace('ND_BIND_IP=0.0.0.0','ND_BIND_IP=127.0.0.1')
  if c.get('ND_BIND_IP')!='127.0.0.1' or ... or c.get('ND_ADAPTER_MODULES'): raise Blocked('RESTRICTED_BOUNDARY_CHANGED')
  ```
  访问地址固定为 `https://127.0.0.1:<端口>`，证书 CN 为 127.0.0.1、有效期 90 天，校名固定为“跃科非学历教育体验学校（合成演示数据）”。
- **后果**：服务只监听服务器本机，老师电脑打不开。手工改成 0.0.0.0 或填写 `ND_ADAPTER_MODULES`（启用统一认证/数据中台适配器必需），后续每条 `开始部署.sh` 命令都会报 `RESTRICTED_BOUNDARY_CHANGED`。已发出的 10d 更新包里的 `manage.py` 同样如此（已核对）。
- **建议**：学校试用改走正式入口：`scripts/deployment_config.py` 生成配置（真实校名、学校分配的域名/IP 和匹配证书），再 `sudo scripts/install.sh --initialize-new-school`。如果坚持用 `开始部署.sh`，就要给它加一个“学校内网”模式，放开绑定地址、访问域名、证书和适配器这四项。

### 2. 后端与任务容器没有出网，CAS 票据校验、数据中台取数、消息推送全部不通
- **位置**：`deploy/compose.yml:27`（api/worker 只挂 `internal`）、`deploy/compose.yml:108-110`（`internal: {internal: true}`）
- **证据**：
  ```yaml
  networks: [internal]
  internal: {internal: true}
  ```
- **后果**：Docker 的 internal 网络没有任何外部路由。浏览器可以跳到 `cas.hnkjxy.net.cn`，但回调后服务端去 CAS 校验 ticket 会连接失败，所以登录失败。明天下午“取数”和“指导测试教师统一认证登录”两个时段都会被它卡住。
- **建议**：新建一个非 internal 的出口网络，只挂给 api 和 worker，db 继续只在 internal。同时在 `.env` 设置 `ND_INTEGRATION_PRIVATE_HOSTS`（列出 CAS、数据中台等校内主机），也可以在宿主防火墙只放行这些目标。到现场先用 `docker compose exec api python -c "import socket;socket.create_connection(('cas.hnkjxy.net.cn',443),5)"` 验证。

### 3. 源码目录的部署文件清单已过期，不能直接从 D 盘源码打包或安装
- **位置**：`delivery/common.py:57-62`（`verify_baseline`）、`delivery/R11_BASE_MANIFEST.json`、`delivery/manage.py:153-163`
- **证据**：只读核对发现源码清单 241 项里有 43 项摘要不符（如 `backend/app/config.py`、`core.py`、`cli.py`），且清单里只有 `20260918_0001` 一个迁移，没有 `20261008_0002_social_training.py`、`20261009_0003_teacher_course_terms.py` 和社会培训模块。源码里的 `manage.py` 也没有 `upgrade` 子命令。相比之下，10d 包内的清单有 281 项，三个迁移都在，自身一致。
- **后果**：从 D 盘源码运行 `开始部署.sh` 会直接报 `R11_BASELINE_CHANGED`。就算绕过去，构建也只复制清单内文件，镜像里会缺社会培训模块和后两段迁移。
- **建议**：另一线程修完 bug 后，按最终源码重建 `R11_BASE_MANIFEST.json` 并打新包，再在包内跑一次清单自检，确认 0 不符、3 个迁移都在。到校只用新包，不用 D 盘源码。

### 4. 安装流程需要外网（拉镜像、pip 装依赖），校内服务器若不能出网会在构建步骤失败
- **位置**：`delivery/manage.py:151`（`docker pull mysql`）、`delivery/manage.py:166`（`docker build --pull`）、`deploy/Dockerfile.api:7-8`（pip 走腾讯云源）
- **后果**：内网服务器无法访问 Docker Hub 或 PyPI 镜像时，`build` 失败，`install` 也就无法进行（install 要求先 BUILT）。
- **建议**：今晚在同架构机器（先确认学校服务器是 x86_64 还是 arm64）构建好 api、frontend 镜像，加上 `mysql:8.4`、`python:3.13-slim-bookworm`、`nginx:stable-bookworm`，用 `docker save` 打成离线包并记录 sha256。到校先 `docker load`，再走 `--pull never` 的安装流程。如果学校服务器能出网，这一项降为 P3。

## P1 首日高风险

### 5. 教师可绕过台账专用权限，读取整院台账明细和附件
- **位置**：`backend/app/social_training.py:145-150`、`backend/app/routes/social.py:777-779`、`backend/app/routes/files.py:62-70`；对照 `backend/app/routes/ledgers.py:283-291`
- **证据**：
  ```python
  elif kind == 'social_resource' and not write and actor.role.kind=='teacher':
      parent=actor.org.parent_id; ... if org_id not in allowed: raise ...
  ```
  这条通用分支只检查“是否本学院”，没有排除 `kind=='ledger'`。专用接口 `require_ledger_role` 明确禁止教师读取。台账编号会写进项目 `data.source.ledger_id`（`ledgers.py:465-468`），项目负责人教师能看到。
- **后果**：教师通过 `/api/social/objects/social_resource/{台账id}` 和附件接口，就能读到全院教师人次分配和原始台账文件，违反招标“教师仅本人”的口径。
- **建议**：在 `scoped()` 的教师分支里对 `obj.kind=='ledger'` 直接 403，或统一调用 `require_ledger_role`。详情、导出、附件列表和下载都走这一个函数，改一处即可。导入真实台账前必须修。

### 6. 课程缺学分时静默按 0 计，生成看似正常的积分/考核
- **位置**：`backend/app/reference_data.py:403`；调用方 `backend/app/services.py:156`、`services.py:193-200`
- **证据**：
  ```python
  if d['counted'] and d['credit'] is not None: total+=Decimal(d['credit'])
  ```
- **后果**：首次同步不完整（课程总库缺学分、学期名识别不出）时，教师授课学分少算甚至为 0。计算照常出分、照常可确认，不会提示缺数据。
- **建议**：计算时如果本周期存在 `counted` 但 `credit is None` 的课程，就返回“待补数据”清单并阻止正式计算或确认，`excluded` 非空时也一样。明天如果来不及改代码，就在试算后先用“授课学分”页的 `problem=true` 筛一遍，清空问题行再正式计算。

### 7. 统一认证登录的老师仍被“首次登录请先修改临时密码”拦住
- **位置**：`backend/app/core.py:144`；账号创建处 `backend/app/excel_io.py:327`（按人事表补建：随机密码、`must_change_password=True`、`active=False`）、`backend/app/routes/admin.py:132`；改密要求旧密码 `routes/auth.py:93`
- **证据**：
  ```python
  if user.must_change_password and not allow_password: raise HTTPException(403,'首次登录请先修改临时密码')
  ```
  `routes/sso.py` 建会话时没有处理该标志。
- **后果**：按人事表补建的账号走 CAS 登录成功后，所有业务接口都返回 403。改密又要输入旧密码，而这个旧密码是谁都不知道的随机串。测试教师会卡在第一步。
- **建议**：统一认证建会话时，对 SSO 绑定账号免除改密要求，或者 SSO 登录成功就清除该标志并记审计。如果明天不改，就要给每位试用老师由管理员“重置临时密码”、启用账号，并当面完成一次改密。

## P2 应尽快修

### 8. 全站本地登录共用一个限流桶，100 次失败即锁住所有人 15 分钟
- **位置**：`backend/app/routes/auth.py:24-37`、`deploy/Dockerfile.api:19`（`--forwarded-allow-ips 127.0.0.1`）、`deploy/nginx.conf:38-41`
- **证据**：nginx 在另一个容器里，后端不信任它转发的地址，`request.client.host` 永远是 nginx 容器 IP，`throttle.attempts>=login_attempts*10`（默认 100）后全站返回 429。
- **后果**：有人连续输错，或者有一个简单脚本撞库，管理员兜底账号也会一起被锁。审计日志里的来源 IP 也全部是 nginx 容器 IP。
- **建议**：把 `--forwarded-allow-ips` 设为 internal 网段（或给 frontend 固定 IP），nginx 已覆盖 `X-Forwarded-For`，可以安全采纳。

### 9. 后端容器时区是 UTC，北京时间 0-8 点日期判断错一天
- **位置**：`backend/app/routes/business.py:101`、`business.py:226-228`、`business.py:305`、`routes/ledgers.py:349`、`reference_data.py:426`（学年按 9 月切换）；`deploy/Dockerfile.api` 和 compose 里 api/worker 都没设 `TZ`（只有 db 设成 UTC）
- **对照**：`social_training.py:39` 显式使用东八区，两套口径不一致。
- **后果**：资质到期提醒、台账“核定日期”、学年归属在凌晨会差一天。小范围试用影响不大，但 9 月 1 日、元旦这类边界会出错账。
- **建议**：给 api/worker 加 `TZ: Asia/Shanghai`（slim 镜像需确认有 tzdata，没有就统一改用 `social_training.today()`）。

### 10. 授课学分列表全量加载后再分页，导入约 22 万条授课记录后可能超时
- **位置**：`backend/app/routes/reference.py:254-266`、`reference_data.py:332-350`
- **证据**：`items=annual_teaching_credits(db,db.scalars(q)); total=len(items); items=items[(p-1)*z:p*z]`
- **后果**：明天计划导入“授课教师课程”约 224,338 行。管理员每次翻页都要全表加载、分组、构造明细，可能超过 nginx `proxy_read_timeout 60s`，也会占用 api 内存（受限 compose 只给 1.5 GB）。
- **建议**：先按年度、教师分页，只汇总当页教师的数据。明天先只取“上学年以后”的增量（计划里已是这个口径），可以缓解。

### 11. 备份只能手动、要停服务、无保留策略、未做过恢复演练
- **位置**：`scripts/deploy_control.py:281-331`（`stop_writers` 后 dump，备份写在同盘 `runtime/backups`），回执状态 `HASH_VERIFIED_NOT_RESTORE_TESTED`
- **后果**：没有定时任务就没有备份。有定时任务时，备份全在同一块盘上，也不清理，磁盘满了数据库会停。至今没有一次实际恢复验证。
- **建议**：装好后立刻配置 cron（更新步骤文档里已给出每周日 3 点的命令，建议试用期改为每天），加保留最近 N 份的清理，并定期把备份拷到另一台机器。首周找一台空机器做一次 `restore --into-empty-school` 演练。

### 12. 部署失败时错误输出全部被吞，现场无法定位
- **位置**：`scripts/deploy_control.py:107-112`、`deploy_control.py:439-440`
- **证据**：`raise ControlError('command failed; sensitive command output suppressed')`，最外层只打印 `BLOCKED: operation failed`。
- **后果**：明天如果迁移、权限或证书出错，只能看到一句 BLOCKED，`--rm` 的迁移容器也不留日志。
- **建议**：把脱敏后的阶段名、命令（去掉参数值）、退出码和 stderr 末尾若干行写进 `runtime/logs/`。现场来不及改的话，出错后手动跑失败那一步的 `docker compose ... run --rm migrate alembic upgrade head` 看原始输出。

### 13. 空闲时 worker 每 2 秒全量校验表结构并重建连接池
- **位置**：`backend/app/worker.py:63-67`、`worker.py:96-107`、`installation.py:88-99`
- **后果**：持续产生 information_schema 查询和新建连接。小范围试用能扛住，但会抬高 MySQL 负载和日志量。
- **建议**：启动时做一次完整校验，循环里只做轻量心跳，引擎跨轮复用。

## P3 建议

### 14. 访问日志会记录 CAS 回调里的 ticket
- **位置**：`deploy/nginx.conf:6`（默认格式含查询串）、uvicorn 默认 access log
- **说明**：CAS ticket 一次性、几十秒过期，实际风险低。建议 nginx 用不含 `$args` 的日志格式。

### 15. 新版本不能直接恢复旧版本的备份
- **位置**：`scripts/deploy_control.py:400-413`、`installation.py:98`
- **说明**：恢复时要求备份库已经是最新迁移版本，与首次安装无关。以后升级失败需要回滚时，要用备份对应版本的镜像来恢复。升级前把旧镜像 `docker save` 留档即可。

### 16. 附件只收 PDF/PNG/JPG，单个 10 MB
- **位置**：`backend/app/routes/files.py:19-42`、`config.py:22`
- **说明**：老师常见的 Word、Excel 证明和 iPhone 的 HEIC 照片都会被拒。上限可以用 `ND_UPLOAD_LIMIT_MB` 调大（nginx 已放到 101 MB）。建议在试用说明里提前告知老师。

## 已核对、未列为问题的部分

迁移链为三段单头（head `20261009_0003`）；生产配置拒绝 SQLite、非 HTTPS、自动建表和样例数据；没有默认会话密钥（会话是随机 token），生产环境关闭了 `/api/docs` 和 openapi；没有 `CORS *`；MySQL 使用 utf8mb4；所有密码由 `secrets.token_urlsafe(36)` 随机生成，不存在默认密码；上传有类型和大小校验、随机存储名、no-follow 打开、下载鉴权，上传目录挂载持久卷；各容器配置了 `restart: unless-stopped` 和日志轮转（20 MB × 5）；积分写入有行锁、幂等和差额计分，未发现并发重复入账。
