# 2026-11-07 立项后运行过程（培训项目、课程、基地、师资）

## 为什么改

老师反映：系统只有申报审批，没有中间过程。项目要一直运行到结项；课程中途会加课时；基地通过后还要看是否在运行。验收人皮老师要求系统简单好用、老师少填。依据管理办法第四条（全生命周期管理）、第十二条（四）（核心事项变更重新备案）。

## 做法：一份档案，三种运行中的动作（不做整份版本化，不改数据库结构）

| 动作 | 谁办 | 要不要审批 | 落在哪里 |
|---|---|---|---|
| 运行记录（记一笔：开班、加课、检查、整改……） | 负责人、所属学院或学校 | 不审批，只追加 | 现有办理记录 workflow_events，不动乐观锁版本 |
| 上传运行材料 | 同上 | 不审批 | 现有附件；已生效的课程、基地、师资也能补传 |
| 申请变更（只审改动的几项） | 同上提出 | 按改动分级（见下） | 变更单是 social_resources 里 kind='change' 的一条，走 approvals 里的 change / change_college / change_hr / change_jwc 审批链 |
| 年度运行确认 | 基地、师资 | 不审批 | 档案 data.annual |
| 停用 / 恢复运行 | 课程、基地、师资 | 不审批，写原因 | 状态 STOPPED；停用不是作废，历史数据都保留 |

- 变更审批期间，原档案照常运行（项目照样导入明细、传材料）。通过后改档案，业务版本号 data.biz_version +1；改前改后的快照就是那条“变更生效：第N版”办理记录的 before/after。
- 生效时会核对申请时的原值，若这期间被别处改过，拒绝生效，请申请人按现状重新申请。
- 一个档案同一时间只能有一份变更在审批。
- 原来的“申请重新备案”（refile）不再在页面出现，改为“申请变更”；在途的重新备案按原路办完，后端保留 refile。

### 变更分级

- 培训项目：换负责人、改培训类别、延期超过 92 天、场地改到校外、预估人次或预计收入变动超过 30%：学院审批 → 学校备案；人次、收入变动不超过 30%：直接生效留痕；其他（预期成果、总学时、一般延期、场地在校内调整）：学院审批。
- 培训课程：学时变动超过 50%：学院 → 学校；面向对象、简介：直接更新；其他：学院。
- 培训基地：地点、级别：学院 → 学校；基地负责人：直接更新；其他：学院。
- 培训师资：业务类别：校内学院 → 组织人事部认定，外聘教务处备案；职称、单位、专业特长：直接更新。
- 学院、学校账号替负责人提出的变更，学院这一级视为提出时已确认（和项目代登记一样）。

## 立项简化

- 老师、教研室提交项目时不再拦“总学时、受众群体、服务面向类型、教学实施方式”，记 data.report_pending=true；结项提交时才要求补齐。
- 项目负责人本人可以在备案后、结项前“补填上报信息”（以前只有学院、学校能补）。补齐后 report_pending 自动清掉。

## 页面

- 菜单不变：培训项目、培训课程、培训基地、培训师资。
- 详情里的三个主按钮（名称按验收人定的）：
  - 培训项目：项目立项（原详情，可申请变更）/ 项目运行（运行档案）/ 项目结项
  - 培训课程：课程申报 / 课程运行 / 课程停用
  - 培训基地：基地申报 / 基地运行 / 年度确认
  - 培训师资：师资申报 / 师资运行 / 年度确认
- 运行档案：进度条、三个主按钮、提醒（培训快结束、没导明细、上报信息没补、年度未确认）、在审变更、运行过程时间线（标“本人 / 学院 / 学校 / 系统自动”）、运行汇总、历次版本。
- 学院、学校在待办中心、审批中心看到“运行中变更”，打开是改前改后对照表，同意或退回。
- 课程停用后，导入参训明细会拦下这门课；师资库里停用的师资显示“已停用”；上报表的基地数不计停用基地。

## 接口

- GET /api/social/lifecycle/{project|course|base|trainer}/{id}：运行档案
- POST …/{id}/notes：记一笔
- POST …/{id}/changes：申请变更（{values:{字段:新值}, reason}）
- POST …/{id}/annual：年度确认
- POST …/{id}/stop、…/{id}/resume：停用、恢复
- GET /api/social/lifecycle/changes/{id}、POST …/changes/{id}/actions（approve / return / withdraw）

## 不需要数据库迁移

新数据都在现有表的 JSON 字段和 social_resources 里。
