## 实现要点

- 审批底座允许“职责型”层级：`LEVEL_DUTY` 把学校、组织人事部、教务处映射到职责码，职责人员在“配置审批职责”里指定；没有改库表。
- 外聘培训师以登记人（学院）为申请人；资质证书编号按原规则脱敏。
- 组织人事部认定、教务处备案审核必须写依据（后端 422、前端必填）。
- 培训场地只在新申报和项目编辑（草稿、退回即重新备案）时强制；已备案项目不追溯。开班前准备清单存 `data.prep`，编辑项目时保留，只提醒不拦截。
- 课程、基地的新字段只存在 JSON 里；未标记的课程仍不产生课程资料记录。

## 真实走查后的改进

按四条新流程用真实账号在浏览器里走了一遍（外聘培训师经教务处入库、一人一技课程经三级入库并显示徽标、校外项目登记一事一议并勾准备清单、省级基地经学院登记到学校入清单），全部走通。顺手改了：

- 培训师、课程、基地、项目表单的主要输入框加了灰色示例提示，点进去输入就消失，不用先删默认文字；办理弹窗的“依据说明”按环节给示例（组织人事部认定、教务处备案审核各有专门示例）。
- 项目表单的培训场地：只有选“校外”才显示一事一议两栏，地点提示随场地类型变化。
- 待办列表里外聘培训师等没有老师的申请，“所属教师或组织”原来显示“学校系统对接”，改为显示所属学院。
