# 权限配置说明（四级角色 × 权限 × 数据范围 × 导出权限）

> 对应采购条款：2.2、2.3、2.6（权限配置说明，我方部分）、2.7（批量授权与角色复制）、2.8（组织/角色调整后范围自动更新）、2.5（越权拦截）。
> 依据代码：`backend/app/permissions.py`（四级权限集合）、`backend/app/core.py`（`org_scope` 数据范围、`Actor` 授权对象、`command` 写操作校验）、`backend/app/routes/admin.py`（账号/角色/组织维护）、`backend/app/excel_io.py`（`require_export_scope` 导出范围）、`frontend/app.js`（`navItems` 菜单、`pageAllowed` 页面准入、`permLabels` 权限中文名）。
> 学校统一认证的身份字段与外部角色映射（2.6 的认证部分）需学校提供接口资料后另行确认，见第 8 节，本文件其余内容为系统内置规则，可直接用于验收核对。

## 1. 权限模型总览

系统权限由四个要素共同决定，缺一不可：

| 要素 | 存放位置 | 决定什么 |
|---|---|---|
| 角色层级 `roles.kind` | 角色表 | teacher=教师、dept=教研室、college=二级学院、school=学校管理部门；决定该角色**最多**能被授予哪些权限码，以及数据范围的计算方式 |
| 权限码 `roles.permissions` | 角色表（JSON 数组） | 菜单权限 + 操作权限 + 导出权限；必须是本层级允许集合的子集（`validate_permissions`），否则账号登录即被拒绝 |
| 所属组织 `users.org_id` | 账号表 | 数据范围的起点。教师/教研室角色绑定教研室，学院角色绑定二级学院，学校角色绑定学校根组织（`org_scope` 强制校验层级匹配） |
| 学校系统管理员标志 `users.is_admin` | 账号表 | 系统管理类接口（账号、角色、组织、周期、参数、接口、移交导出、运维）额外要求 `role.kind=='school'` 且 `is_admin=true`（`Actor.require_admin`）。学校层级角色**不自动**成为系统管理员 |

关键原则（代码强制，非界面约定）：

1. **服务端校验**：每个接口在服务端调用 `actor.require(权限码)` 与 `actor.scope(...)`；隐藏菜单只是体验优化，不是安全控制。
2. **数据范围不逐人配置**：范围 = 角色层级 + 当前所属组织在组织树中的位置，每次请求实时计算（`org_scope`）。
3. **不能授予超出本人的权限**：管理员新增/调整账号或角色时，目标权限必须 ⊆ 操作人自己的权限（`admin.py` 中 `set(role.permissions)<=a.permissions`）。
4. **越权一律拦截并留痕**：401/403/404 访问由访问日志记为 `DENIED`（`audit_events.result`），可在“操作日志与安全审计”按结果筛选。

## 3. 数据范围（`core.org_scope` 与 `Actor.scope`）

| 角色层级 | 必须绑定的组织层级 | 可见组织范围 `org_ids` | 业务数据范围（教师集合） |
|---|---|---|---|
| 教师 teacher | 教研室 dept | 本人所在教研室 | **仅本人**：`teacher_id == 当前用户`；且 `check_teacher` 拒绝访问他人数据 |
| 教研室 dept | 教研室 dept | 本教研室 | 本教研室内**有工号**的账号 |
| 二级学院 college | 二级学院 college | 本学院 + 所属全部启用教研室 | 本学院及下属教研室内有工号的账号 |
| 学校管理部门 school | 学校根 school | 学校根 + 全部启用学院和教研室 | 全校有工号的账号 |

计算规则（每次请求实时执行）：

1. 校验组织存在且启用、角色层级与组织层级匹配，否则 403“角色与组织层级不匹配”。
2. 向上校验到学校根，链路中任何一级停用或层级异常即 403“组织关系无效/组织层级不完整”。
3. 向下展开所有**启用**的下级组织（停用的教研室及其教师自动移出上级范围）。
4. 业务查询统一使用 `actor.scope(teacher_id列)` 生成子查询，列表、统计、驾驶舱、导出共用同一范围，保证同源同口径。

## 5. 操作权限与流程环节

| 业务 | 教师 | 教研室 | 二级学院 | 学校管理部门 |
|---|---|---|---|---|
| 培训台账 | 查看本人；对本人记录提出核对 | 录入/更正本教研室台账；Excel 导入 | 同左（本学院范围） | 同左（全校）；无数据中台时可人工补录 |
| 教师资质 | 新增/编辑本人资质、上传佐证、提交、撤回 | 审核通过/退回本范围资质（不能审核本人） | 同左 | 同左 |
| 积分 | 查看本人流水、确认本人积分、提出核对 | 查看本范围 | 查看本范围 | 规则维护/试算/启用、计算、单人/单项重算、人工调整与冲销 |
| 教师考核流转 | `TEACHER` 环节本人确认 | `DEPARTMENT` 环节确认或退回 | `COLLEGE` 环节确认或退回 | `SCHOOL` 环节审核、`READY` 归档；可退回 |
| 组织考核 | — | 本教研室结果组织复核 | 本学院结果组织复核 | 规则维护、计算、学校审核、归档 |
| 数据核对 | 提出申请（台账/积分/考核） | 复核本范围申请 | 复核本范围申请 | 复核全校申请 |
| 系统管理 | — | — | — | 账号、角色、组织、周期、参数、接口、审计、运维、移交（需系统管理员） |

服务端硬性约束（`calculations.py` 考核流转）：不能越级确认、不能审核本人考核、存在未解决核对时不能确认或归档、只有学校层级可归档 `READY` 状态结果；资质审核同样不能审核本人。

导出安全机制：

- 导出为后台任务，创建时冻结当前“授权指纹”（账号、授权版本、角色及版本、组织、范围教师集合、权限）；下载时再次比对，**权限或组织变化后旧导出文件不能下载**（409“权限范围已变化，请重新导出”）。
- 只能查看、重试、下载**本人创建**的导出任务；下载时校验文件 SHA-256 并写审计“下载后台导出”。

## 7. 日常配置操作

入口：系统管理 → 组织、账号与权限（需学校系统管理员），所有保存都要求填写原因，并写入审计（调整前值、调整后值、原因）。

### 7.1 按角色批量授权（2.7）

1. 打开“角色与授权”分区，在目标角色行点击“批量授权”。
2. 弹窗显示“本次授权影响”：角色层级、数据范围说明，以及会影响所有绑定此角色的账号。
3. 勾选/取消权限（只列出该层级上限 ∩ 操作人自身权限），设置角色启用状态，填写原因后保存。
4. 服务端（`PUT /api/roles/{id}`）校验：权限属于层级上限、不超过操作人权限、每个层级至少保留一个启用角色、至少保留一位可用学校系统管理员；保存后角色 `version+1`。
5. 生效方式：绑定该角色的**所有账号**在下一次请求即按新权限执行（权限每次请求从角色表实时加载），无需逐人修改。

### 7.2 复制已有角色（2.7）

1. 在源角色行点击“复制角色”，填写新角色编码、名称和原因。
2. 服务端（`POST /api/roles`，`copy_from`=源角色）复制源角色的层级、全部权限码与启用状态，形成独立新角色。
3. 由于数据范围由“层级+组织”计算，复制角色即同时复制了**菜单权限、操作权限和数据权限**；随后可对新角色执行 7.1 批量授权做差异调整。
4. 不能复制包含超出操作人权限的角色（403“不能复制超授权角色”）。

### 7.3 新增账号与分配角色

1. 账号管理 → 新增账号：填写账号、姓名、工号（教师角色必填）、职称、所属组织、角色、临时密码、原因。
2. 服务端校验组织与角色层级匹配、角色不超过操作人权限；新账号 `must_change_password=true`，首次登录必须改密。
3. 临时密码通过学校安全渠道交接，系统不在页面或审计中保存明文。

### 7.4 组织或角色调整后的效果（2.8）

| 调整动作 | 系统行为 | 是否需要逐人改数据权限 |
|---|---|---|
| 修改账号的所属组织或角色（`PUT /api/users/{id}`） | `auth_version+1`，立即删除该账号全部会话，用户需重新登录；新范围按新组织/角色实时计算；旧导出文件不可下载 | 否 |
| 调整组织上级（如教研室划转到另一学院） | 组织树变化后，原学院范围自动移出、新学院范围自动纳入该教研室及其教师（下一次请求生效） | 否 |
| 停用组织 | 该组织及其下级组织的账号因组织链无效被拒绝访问；上级范围自动排除这些组织 | 否 |
| 调整角色权限（批量授权） | 绑定该角色的所有账号下一次请求即生效；已发起的幂等写请求如授权指纹变化，重放返回 409 | 否 |
| 数据中台教师人事入库导致教师组织或在职状态变化 | 自动更新本地账号组织/启用状态并 `auth_version+1`，旧会话失效 | 否 |
| 停用账号 / 重置密码 | 会话全部失效；重置后需首次登录改密 | — |

验收核对建议：调整后用被调整账号重新登录，核对菜单、列表条数、统计数和导出范围是否与新组织一致；同时在审计中检索“调整账号权限 / 调整角色授权 / 调整组织 / 组织启停”。

## 8. 待与学校确认事项（统一认证映射，2.6 认证部分）

系统当前规则：统一认证只负责“确认是谁”，外部角色仅作为证据记录，**不直接授权**；本地账号的角色、组织、数据范围仍以本系统为准（`LOCAL_ROLE_AUTHORITATIVE`）。统一认证身份通过稳定标识/账号/工号映射到本地账号，无映射时提示“尚未建立该人员账号映射，请联系学校管理员”。
