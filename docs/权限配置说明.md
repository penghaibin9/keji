# 权限配置说明（2026年10月13日）

本说明按当前权限、账号、人事对应及社会培训审批代码核对。界面菜单是入口，实际每次读写、下载与导出都由服务端再次校验。学校真实审批名单与人员隐私范围由学校签认；本文件不代替名单授权。

## 一、四类角色与数据范围

| 角色 | 所属组织 | 数据范围 | 主要工作 |
|---|---|---|---|
| 教师 | 教研室 | 本人业务数据；其他公开信息仍按具体发布与授权规则 | 个人数据看板、授课学分、本人资质、积分申报与确认、本人考核及核对申请。 |
| 教研室 | 教研室 | 本教研室有权范围 | 本组织培训数据维护、资质审核、教师考核教研室环节、数据复核。 |
| 二级学院 | 学院 | 本学院及启用的下属教研室有权范围 | 学院统计与台账、学院考核确认、项目与社会培训业务。 |
| 学校管理部门 | 学校根组织 | 全校有权范围 | 学校规则、计算、审核、归档、学校统计；系统管理另须管理员身份。 |

学校角色不自动成为学校系统管理员。维护账号、组织、角色、参数、接口、运行和整体移交等接口，按具体操作还须具有学校系统管理员身份及相应权限。不能授予超出操作人自身的权限；角色权限必须在本层级允许范围内。

组织、角色及启用状态会影响动态范围。停用组织、账号或角色及组织链异常会阻断访问。姓名相同不代表同一教师；账号对应以实际工号与已核验身份关系为准。

## 一（补充）、一人多身份与组织负责人

一个人可以同时有几个身份，例如本人是老师，同时是教研室负责人、学院负责人。账号的“主身份”是账号里的角色和所属组织；其余在账号“编辑”里的“兼任身份”添加，每个兼任身份同样按“教师和教研室负责人绑定教研室、学院负责人绑定二级学院”校验。学校管理员只能作为主身份。

登录后默认用主身份。有兼任身份的人，页头右上角出现“当前身份”下拉框，旁边提示其他身份还有多少待办；切换后菜单、数据范围、审核级别都按切换后的身份判断，切换留审计。任何身份都不能审核本人的考核、资质和授课。

组织负责人在“账号与权限 → 组织机构”里设置：每个学院、教研室显示负责人，点“设置负责人”从本组织在职、有工号的老师里选，相当于给这位老师加一个负责人兼任身份，原来的教师身份不变。一个组织可以设几位负责人，任何一位都能办理。移除负责人后，正在用该身份的会话失效。

缺负责人时自动上交上一级办理：教研室没有可用负责人，教研室这一级由学院负责人代办；学院也没有，由学校代办；学院没有负责人，学院这一级由学校代办。授课认定同理，学院和教研室都缺负责人时由学校系统管理员认定。代办和同一人连审两级（同一人既是教研室又是学院负责人）都允许，办理轨迹上标“代缺位……办理”“同一人连审”，学校可以看到。

输错密码被锁定时，管理员可以在账号列表点“解锁”，不改密码。

## 二、统一认证只提供身份

“学校统一认证登录”通过学校身份验证后，仍需要有效的本地账号对应；本地账号的角色、组织、启用和待授权状态决定权限。外部身份携带的角色不自动获得本地权限，也不自动获得学校系统管理员身份。

正常学校认证会话不要求修改本地临时密码；改用本地账号认证时，尚未完成的首次改密仍须完成。学校未登记回调、校验地址、身份字段、组织对应及测试账号时，不能宣称真实认证联通。

## 三、人事调岗与授权待确认

人事单位变化后，系统将账号标记为“人事调岗 · 授权待确认”，原授权不能继续作为业务授权使用。管理员到“账号与权限”打开账号“编辑”，核对学校最新归属、角色、启用状态和职责，再点击“确认授权并保存”，记录依据与原因；旧会话失效，本人重新登录。

调岗不替学校推断新审批职责；同时检查该账号关联的社会培训职责与回避安排。已生成的导出、旧下载和待办按当前权限再次校验，不因原先有权限永久保留访问权。

## 四、社会培训职责与回避

“规则与配置”→“社会培训制度口径”→“配置审批职责”。职责与角色是两层控制：人员须具备操作权限、数据范围、相应职责，并且无需回避，才能在当前环节办理。

| 职责 | 主要办理环节 | 学校应确认的内容 |
|---|---|---|
| 二级学院院长 | 本范围积分初审及相关更正初审 | 实际学院归属、替代人员与本人回避。 |
| 归口学院复审 | 项目备案与结项、积分及更正复审、公示复核 | 归口名单、可见范围与业务责任。 |
| 分管副校长 | 积分及更正审批 | 权限、范围及回避安排。 |
| 教学秘书 | 积分归档入账、归档追加更正差额 | 建议落实至少两名合格人员，保证本人事项有其他人可办。 |
| 财务核验 | 学院年度考核资金依据核验 | 财务负责人及替代人员。 |
| 成果核验 | 学院年度考核成果依据核验 | 成果管理负责人。 |
| 纪检核验 | 学院年度考核资金管理与投诉等职责 | 核验责任、范围与利益冲突。 |
| 委员会评审 | 学院年度考核评分、公示及相应归档环节 | 委员会名单及制度授权。 |

本人申报、本人考核及已登记利益冲突须回避。发送复核前检查后续环节是否存在有权且无需回避的人员；缺人应先配置替代职责，不能把本人事项改名交自己审核。

具体页面只显示当前人员可办理的按钮。角色、职责或范围发生变化时，历史曾办理过不等于当前仍可办。社会培训学院台账按学院、学校角色核验；教师在“个人培训”查看分给本人的数据。

## 五、核心业务操作控制

| 业务 | 控制要求 |
|---|---|
| 教师资质 | 本人维护和提交；有权审核人员核验，不能审核本人；当前版本材料与状态一起校验。 |
| 教师积分 | 本人核对和确认；计算、调整、解锁由获授相应学校权限者执行，调整追加差额并留痕。 |
| 教师考核 | 教师、教研室、学院、学校按环节办理；未解决核对或来源变化会拦截确认和归档。 |
| 组织考核 | 在本组织权限范围复核；学校有权人员审核归档，规则必须先试算再启用。 |
| 社会培训积分 | 院长初审→归口复审→分管副校长审批→教学秘书归档；各环节另核验职责、回避与来源。 |
| 学院年度考核 | 学院自评与相关职能部门核验、委员会办理；缺制度依据或核验条件不能发布正式结果。 |
| 表格导入 | 类型、人员组织范围和当前授权分别校验；有错误整批不能入库，放弃保留原预览和审计。 |
| 代码对照 | 学校系统管理员在对接入口管理，填写依据；替换整类码表应先确认权威完整版本。 |

批量只支持当前页的社会培训积分认定与教师考核同类同环节事项；每条仍单独执行原单条校验。本人的业务不可勾选。连续办理只记住当前页次序，不代替审核。

## 六、导出、附件和审计

教师导出为本人范围，教研室和学院分别为本组织范围，学校为相应全校权限范围。后台执行与下载重新检查账号、角色、组织与授权变化；旧导出在撤权后不能继续下载。只能查看或下载本人创建且当前合法的任务，不通过复制下载地址扩大范围。

附件上传、查看、下载和解除都核验业务对象权限及材料状态。归档件使用冻结原证据，不因当前资料更新而改写。整体结构化移交、审计导出与初始化配置资料还需相应管理员及移交权限。

“安全提示与操作日志”按人员、时间、模块和结果核对操作。授权调整、规则、导入、导出、审批和归档须保留原因及依据；管理员不能通过隐藏菜单关闭后端校验。

## 七、管理员上线核对与签认

逐人核对工号、账号、组织、角色、管理员身份及社会培训职责；使用正常教师、教研室、学院、学校账号分别检查可见范围、本人回避和越权拒绝。确认调岗后旧会话与旧文件访问失效，避免用一个管理员账号代替四类角色测试。

学校签认项：角色人员名单、审批替代人员、利益冲突、个人信息可见范围、认证字段及组织对应、账号交接与临时账号停用日期。缺学校资料的项目保留待确认，不填已完成。
