## 四角色的责任与交接

| 角色 | 本轮负责办理 | 可见范围 | 交给下一位什么 |
| --- | --- | --- | --- |
| 普通教师 | 本人资质申报与补正、本人积分申报与确认、本人考核确认、提出异议 | 本人；本人负责或参与项目的授权信息 | 完整材料、本人确认、需核对的问题 |
| 教研室负责人 | 资质审核、本室积分核对、本室教师考核确认 | 本教研室，相关项目按授权只读 | 审核意见、已解决的核对、教研室确认结果 |
| 二级学院 | 项目申报与实施明细、结项报送、院长积分初审、学院考核确认、学院台账和年度自评 | 本学院及下属教研室 | 待备案项目、待结项材料、初审结果、学院确认结果 |
| 学校管理部门 | 制度与周期准备、项目备案与结项核验、积分复审与审批归档、考核审核归档、台账核定与年度核验 | 学校授权范围；具体操作另受职责限制 | 可追溯的正式认定、归档结果和统计结果 |

四个使用角色不等于四级积分审批。积分顺序为“院长初审 → 归口学院复审 → 分管副校长审批 → 教学秘书归档”。第二至第四级属于学校角色内的不同职责，按实际配置准备不同账号；申报人及已申报利益冲突者必须回避。没有合法审批人时，记录为前置条件缺失，不放宽权限。

## 共用业务样本

使用以下最小样本，让各页面的结果能够相互核对：

| 样本 | 用途与预期 |
| --- | --- |
| 1个普通社会培训项目、1门关联课程、1个模块式核算单元 | 学院建立，学校备案后录入明细，再办理结项 |
| 30名符合条件的参训人员、2名共同授课教师 | 组织人次按同一核算单元统计为30，不能因2名教师变成60；教师积分分别依已确认规则核定 |
| 合成到账收入3000元及匹配的资金来源、分配依据 | 各层组织收入不因共同授课重复累计；个人金额依确认分配回读，不猜分配比例 |
| 主项目满意度96%及八类结项材料 | 检查结项核验与自动登记校级成果，重复请求不得产生重复成果 |
| 主教师的1份资质申请 | 检查申报、退回、补正、审核及考核依据引用 |
| 1条教师本人参训记录 | 验证“教师参加培训”与“教师授课”分开，不增加授课收入、授课人次 |
| 同院另一教研室教师、另一学院教师各1名 | 检查教研室与学院范围边界，不参与主项目 |
| 1份学院台账、1个开放考核周期、1版已确认制度及教师考核规则 | 核对项目、人员、年度、人次、收入、积分和考核来源 |

主项目日期按候选测试日期和已确认工作日历安排，确保申报在合法期限内。15个工作日申报期限、年度截止和5个完整工作日公示另设边界用例；日期模拟仅用于隔离测试，不修改电脑或生产时间，不伪造已经完成的公示。

积分与考核分数先用已确认规则建立独立预期明细，再与系统比对。不以系统自己的计算结果充当预期；学校未确认的口径应显示待确认并阻断正式出分。

## 主线走查顺序

每步均检查：入口是否可发现、表单是否可填写、保存是否成功、下一角色是否收到正确待办、刷新后是否保留、历史记录是否完整。每次角色交接都由下一角色正常登录后接续办理。

| 步骤 | 办理角色与入口 | 必须完成的操作 | 通过标准 |
| --- | --- | --- | --- |
| 1 | 学校，规则与配置、账号与权限 | 核对周期、规则试算、制度、校历、审批职责和组织范围 | 未试算规则及未确认制度不能正式出分；各角色权限明确 |
| 2 | 教师，个人培训或教师资质管理；教研室，统一待办 | 资质申报 → 教研室退回 → 教师补正 → 教研室审核通过 | 退回原因可读，原材料与新版本留痕，完成待办消失 |
| 3 | 学院，培训项目管理 | 建立草稿、上传申报材料、提交备案 | 保存后能继续办理同一项目；学校待办指向准确对象 |
| 4 | 学校归口复审人，统一待办或项目详情；学院补正 | 先退回一次，学院补正后重新提交，学校备案 | 无越级操作；退回意见、补正材料和备案依据可追溯 |
| 5 | 学院，项目实施明细与培训课程管理 | 关联课程，预检并确认参训和授课明细 | 预检不入库；确认整批入库；再次确认不重复；组织人次与个人授课分别核对 |
| 6 | 学院，项目结项；学校归口复审人核验 | 报送收入、资金分配、满意度及材料，逐项核验后结项 | 材料不齐不能结项；八类核验完成；收入、人次、成果在关联页面一致 |
| 7 | 教师，个人培训 | 查看本人参与项目、积分依据，上传认定材料并提交本人积分申报 | 只列可申报的本人项目；未结项、超期、口径未确认等情形解释清楚并正确阻断 |
| 8 | 学院院长及学校各审批职责人员 | 初审 → 归口复审 → 分管领导审批 → 教学秘书归档；途中测试一次退回补正 | 每级待办交接正确；本人回避；未归档不正式入账；归档只入账一次 |
| 9 | 教师，教师积分激励与个人培训 | 核对已归档认定、本人余额及计算依据，完成积分确认 | 原认定、余额、明细和导出一致；不得再用旧汇总规则重复计算社会培训积分 |
| 10 | 学校，三级考核管理；教师、教研室、学院依次办理 | 生成考核 → 教师确认 → 教研室确认 → 学院确认 → 学校审核 → 学校归档 | 各阶段归属正确；有未解决核对或来源变化时阻断；禁止自审和越级确认 |
| 11 | 各角色，详情、附件与导出下载；学校，日志与运行、驾驶舱 | 查看归档依据、下载附件、导出并核对汇总；退出后重新登录、深层页面刷新 | 历史结果冻结；附件内容和权限正确；导出范围与页面一致；业务操作留痕 |

项目收入、人次、教师个人积分、学院年度考核分别核对。组织统计不能通过把教师个人明细简单相加来计算共同授课项目收入和人次。

## 相关支线

| 支线 | 必查操作 | 通过标准 |
| --- | --- | --- |
| 学院台账与口径检查 | 上传合成台账 → 人员匹配 → 明确关联项目 → 逐行核定 → 导出 | 同名教师按明确身份区分；同名项目需明确关联；新版本不串旧行；待核定与已核定清楚区分 |
| 教研室发起积分核对 | 教研室指出问题 → 教师说明或同意 → 按结果进入学院裁定或更正审批 | 核对未办结前阻止考核确认；结论、原因和后续更正能互相定位 |
| 归档积分更正 | 对已归档认定追加更正，再逐级审批 | 原认定保留，仅追加差额；考核已归档时按允许的更正周期办理，不解锁改写历史 |
| 教师本人参训 | 管理角色依法登记或更正，教师查看本人记录 | 与授课入口、业务名称、数据汇总分离；教师不能越权新增或查看他人 |
| 学院年度考核 | 目标下达 → 学院自评 → 各职责核验 → 委员会评分 → 公示 → 异议处理 → 归档 | 待核定数据不能假装正式结果；未满公示期或异议未办结不能归档；零加分无需虚构加分依据 |

## 走查修复的三轮安排

第一轮按主线办理。每一步先记录预期和当前版本，再由正常账号操作，核对页面与服务器保存结果，接收下一角色待办。发现阻断时先保存复现证据，查清是资料缺失、未配置职责、未确认制度、外部依赖还是产品缺陷。

第二轮执行异常与边界。重点覆盖权限、重复入账、并发覆盖、历史冻结、工作日、公示、来源变化和附件。共用表单与返回路径在主线和支线同时检查，避免只修某一个页面。

第三轮复验修复。对确认的缺陷先增加最小回归检查，再以局部补丁修复共同根因；复跑触发用例、直接受影响的回归及完整主线，最后重新登录四类角色取证。没有证据的状态保持“待验证”。

| 修复顺序 | 范围 | 关闭条件 |
| --- | --- | --- |
| 第一优先 | 越权、重复入账、覆盖新数据、改写归档历史、附件泄露 | 原复现失败方式被阻断，正常流程仍通过，无原数据损失 |
| 第二优先 | 登录不了、提交失败、审批或待办无法交接、状态无法继续 | 四角色完整交接，退回补正后可继续，下一角色接收正确对象 |
| 第三优先 | 人次收入重复、积分依据不符、周期与公示错误、统计导出不一致 | 独立预期、办理结果、台账、汇总和导出对得上 |
| 第四优先 | 返回丢输入、中文难懂、手机排版、图片样式和操作反馈 | 核心任务能完成，用户知道当前状态、原因和下一步 |
