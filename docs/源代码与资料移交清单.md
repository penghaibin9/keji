> 移交方式：【待填：光盘/移动硬盘/采购人代码仓库地址】　　移交日期：【待填】　　版本：R11（迁移基线 `20260918_0001`）

## 一、移交原则

1. 源代码以明文文本交付，可在采购人环境独立构建（`deploy/Dockerfile.api`、`deploy/Dockerfile.frontend`）和部署运行。
2. 业务数据以开放格式（UTF-8 CSV + JSONL + 原始附件 + JSON 结构描述）移交，附逐文件 SHA-256 清单和校验脚本；不使用专有格式或加密字段。
3. **不在介质中交付任何真实密钥**：数据库密码、管理员临时密码、外部接口凭据、TLS 私钥由学校服务器管理员按《部署手册》在 `deploy/secrets/`、`deploy/.env`、`deploy/tls/` 中自行配置；移交包也不含密码哈希、会话、登录限流、命令回执和接口密钥值（接口配置仅保留密钥环境变量名称）。
4. 每项移交物需记录文件名/路径、SHA-256（或提交号）和份数，双方核对后签字。

## 六、学校业务数据与配置移交

### 6.1 初始化配置与数据字典（学校专属配置）

1. 学校系统管理员登录 → 系统管理 → 运维与交付 →“下载初始化配置与数据字典”（`GET /api/delivery/configuration.xlsx`，需 `data.export` 权限及系统管理员）。
2. 工作簿包含：组织机构、角色权限、基础参数与字典、考核周期、接口配置（参数与字段映射，不含密钥值）、接口数据类型、定时同步计划、数据库字典。

### 6.2 全校开放格式业务移交包（`excel_io._handover_zip`）

1. 学校系统管理员 → 表格导入中心 →“生成结构化移交包”，明确确认后创建后台任务（`POST /api/exports`，`kind=handover`，`confirmed=true`，不接受筛选条件）。
2. 后台在**单一只读数据库快照**中导出（MySQL `START TRANSACTION WITH CONSISTENT SNAPSHOT, READ ONLY`），保证各表一致；已归档考核在导出前校验归档快照。
3. 在“导出与任务中心”等待状态为“已完成”后下载 `学校业务开放格式移交_<任务ID>.zip`（下载时重新校验权限与文件 SHA-256，并写审计）。
4. 移交包内容：

| 内容 | 路径 | 说明 |
|---|---|---|
| 业务表 CSV | `data/<表名>.csv` | UTF-8，电子表格可直接打开（为防公式注入，个别值可能加单引号前缀） |
| 精确类型数据 | `typed/<表名>.jsonl` | 金额/日期/时间为精确字符串，JSON 字段保留结构；**数据迁移以此为准** |
| 数据库结构 | `database_structure.json` | 全部表的列、类型、可空、主键、外键 |
| 初始化配置 | `delivery/initialization_configuration.json` | 组织、角色、周期、参数字典、接口配置与映射、定时计划 |
| 数据字典 | `delivery/database_dictionary.json` | 字段级字典（与《数据字典》同源） |
| 接口数据目录 | `delivery/interface_data_catalog.json` | 三类接口的数据类型清单 |
| 原始附件 | `attachments/<附件ID>.<扩展名>`、`attachments_manifest.json` | 原文件名、SHA-256、大小、关联业务对象与教师 |
| 文件清单 | `manifest.json` | 每个文件的大小与 SHA-256、每张表的列、行数、主键、列类型 |
| 说明 | `README.txt` | 编码与使用说明 |

导出的业务表（40 张）：organizations、roles、users、periods、settings、training_records、qualifications、qualification_revisions、rules、point_balances、point_entries、assessments、workflow_events、organization_assessment_rules、organization_assessments、organization_assessment_metric_evidence、teacher_hr_profiles、training_projects、training_courses、training_classes、teacher_participations、inbound_batches、inbound_rows、integration_schedules、sync_items、sync_call_logs、record_revisions、calculation_batches、rule_trials、organization_rule_trials、disputes、import_jobs、import_rows、tasks、task_attempts、notices、connection_checks、attachments、connections、audit_events。

明确不移交：密码哈希、授权版本、登录失败计数与锁定时间、附件内部存储键、会话令牌与 CSRF、任务租约，以及 auth_sessions、login_throttles、command_receipts、installation_provenance、runtime_state、mutation_guards 6 张内部表（合计 40 + 6 = 46 张）。

### 6.3 移交包校验（`scripts/verify_handover.py`）

```bash
python3 scripts/verify_handover.py 学校业务开放格式移交_<任务ID>.zip
```

校验内容：ZIP 路径安全（无绝对路径、`..`、符号链接）、必需文件齐全、`manifest.json` 中每个文件的大小与 SHA-256、manifest 文件集合完整、CSV 不含禁止移交的内部字段、接口配置不含疑似密钥字段、附件字节与清单一致。输出 `PASS` 才可签收；结果中 `disaster_restore_proven=false` 表示该包**不是灾备文件**（灾备见《管理员操作手册》第 10 节数据库备份与恢复）。

### 6.4 数据库完整备份（灾备，按需）

如学校需要完整数据库副本，按《管理员操作手册》10.1 执行 `scripts/backup.sh`，备份目录（`database.sql.gz` + `files/` + 清单）由学校自行保管；恢复只能使用 `scripts/restore.sh --into-empty-school`。
